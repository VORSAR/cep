# The Fool's pre-mortem — Phase 1 architecture baseline

**Role:** the-fool (adversarial reasoning, pre-mortem mode). I wrote none of the documents under review.
**Scenario assumed true:** it is 2027-02-01, three months after the baseline was ratified. Phase 1 — the Agent Kill Switch MVP — shipped late, broken, or not at all, *despite the architecture baseline being followed*.
**Inputs read on commit 1b9fff8:** ARCHITECTURE.md; ADR-0001…0009; roadmap Phase 1 (02-roadmap.md) incl. exit criteria and attack gallery; sprint model §2/§3/§6; DEVELOPMENT.md; SEMANTICS.md (§2 especially); SPEC.md §6.8/§8; errors.md (57 codes); the corpus (9 valid / 24 invalid files); checks/executor.py.
**Not in scope:** style, praise, re-litigating ratified product decisions. The four windows, the attack gallery and the text operators ARE the MVP; only sequencing and cutting *within* that decision is questioned.

---

## 1. The failure narrative (as if it happened)

It is 2027-02-01. There is no `v0.1.0` tag. `main` has the gate, a parser, and a clock package nobody fully trusts.

**Week 1–5: "S1" was four sprints wearing one card.** ADR-0005 decreed S1 = gate, then playback, then conformance runner, "before any operator." At S1's plan check the coordinator discovered what the ADR had hidden in plain sight: playback "must exercise the real runtime" (ADR-0005 rejected the stub alternative), and the conformance runner "executes every expect block," which requires `internal/event`, `model`, the *full* goyacc grammar (the differential needs it whole), the 34-code validator, `clock`, `partition`, and a runtime skeleton. Seven packages, one owner per file, at most two agents at once, lanes ≤ 8 days. The card was split mid-flight — the thing the ground rules forbid — and the first green `make strict-gate` landed at the end of week 5. The owner, answering plan checks and dependency sign-offs in evening sessions, became the calendar: a median 2.5 days between a gate question and its answer, six gates per sprint.

**Week 3: the conformance runner refused the flagship.** The kill-switch example's first `expect` block requires `resource in SensitiveResources` to be true for `'vault'` — and SPEC §6.8 defines `given` sections for *streams only*. There is no table-fixture syntax and no table record in the merged-log format (ADR-0005 §3). Against an empty table the read step never matches and the frozen spec's own flagship example fails `E-EXP-001`. Stop-the-line; a spec change-log entry; an owner decision; a week.

**Week 8: the clock misread that conformance could not see.** The clock lane's agent implemented `clock.Instance.Observe(sid, ts)` exactly as ADR-0004 draws it: per rule instance. Admission watermarks were therefore computed from *the events routed to that key*. Every ported harness test passed — the Python executor feeds one engine externally supplied watermarks, and playback's end-of-log `wm → +∞` flush emits the right outputs with the right timestamps, so the conformance suite was green. The demo was not. Agent `a1` performs a sensitive read and goes quiet — the attack itself — while other agents keep the streams busy, so the per-stream `idle after` ticker never fires; `a1`'s instance never observes another event; its construct clock froze at `09:58`; the absence deadline at `10:05` never fired, and neither did the TTL purge (also clock-driven). The kill switch never fired *for exactly the agent that attacked*, and per-key state leaked forever. The fix was not a patch but a design: a per-stream watermark is shared state across shards, which ADR-0006's "no shared mutable state between shards" rule forbids — so the runtime had to grow a wm-broadcast message the ADRs never mention. Two weeks, plus a re-review of every timer consumer.

**Week 10: determinism died on a second machine.** CI (Linux) and the owner's Mac disagreed byte-for-byte on `02-cron-digest`: `time.LoadLocation` had read two different system tzdata versions. The same week, the http source's `map[string]any` decode turned an int64 span id above 2^53 into a rounded float64 — caught only because a gallery fixture used a realistic 64-bit id.

**Week 12: the scope arithmetic nobody ran.** With the kill-switch path barely demo-able, still ahead lay: four windows with conformance, five text-operator families, the Go builder and the parity test, three sources, three sinks, `cepd`, `cep validate/test/fmt`, metrics, the demo kit, the quickstart under 15 minutes, and an attack gallery of ≥5 cited, runnable examples in both front-ends. At the measured pace — one full-loop sprint ≈ 3 weeks wall-clock including owner latency and a blind three-reviewer panel per semantic sprint — the honest forecast for the exit criteria read *June 2027*. Phase 1 had quietly been an 8–12 sprint phase since the day the windows and the gallery entered the slice; the baseline sequenced it as if it were four.

Root cause of root causes: every document assumed the others' hardest promise was already kept — the ADRs assumed agent-sized sprints, the sprints assumed owner availability, the conformance story assumed the spec's own examples were runnable, and the determinism promise assumed per-instance interfaces meant per-stream semantics. Nobody owned the seams between the promises.

## 2. Ranked root causes

Ranking = likelihood × impact. Each cause names the **shared assumption** the architect and coordinator both hold (and therefore cannot see), the **evidence** in the documents, and the **cheapest mitigation**.

### RC1 — The clock's watermark scope is ambiguous: per-instance `Observe` vs per-stream semantics. The flagship silently never fires in live mode. — Likelihood: HIGH · Impact: CRITICAL

**Shared assumption:** "ADR-0004 is verbose enough that a coding agent can implement the clock without inferring anything" — and "conformance green = semantics right."

**Evidence:**
- ADR-0004 §1 puts `Observe(sid int, ts int64) (streamLate bool)` on the **per-rule-instance** interface. An agent implementing literally what the interface shape says computes admission watermarks from only the events routed to that key.
- SEMANTICS §2.1 (and ARCHITECTURE §5 step 4: "tracks, **per stream**: admission watermark") requires `max(event time seen)` over the *whole stream*. The reference executor (`checks/executor.py`) computes watermarks globally per stream and feeds the matcher "externally supplied watermarks" — the harness cannot even express the per-instance misread, so **the ported table tests pass either way**.
- Playback masks it too: ADR-0005/SEMANTICS §2.1 flush `wm → +∞` at end of log, and the emitted match timestamp is the *match end* (§6.4), not the fire time — so byte-identical conformance output is achievable with a clock that, live, never advances a quiet key. The failure mode is precisely the attack scenario: the agent that reads and goes dark. `idle after` does not save it — the ticker is **per source stream** (ADR-0004 note), and the stream is not idle, only the key is. TTL purge is clock-driven (ADR-0006 §3), so state also leaks unboundedly.
- The correct implementation (shared per-stream wm) collides with ADR-0006 §1: "no shared mutable state between shards." The agent's two locally-defensible options are both wrong; the resolution (ingest owns stream wms and broadcasts advances to shards as mailbox messages, shards re-derive each due instance's construct clock) appears in **no document**.
- Four smaller ADR-0004 misread traps of the same class: (a) is `virtualFloor` = `virtual_now` or `virtual_now − d`? SEMANTICS §2.1 says `virtual_now − d`; the ADR interface comment doesn't say who subtracts `d` — get it wrong and playback fires absences `d` early, breaking the live/playback guarantee. (b) `idleFloor`'s *value* is defined nowhere ("raised by idleness" — raised to what?). (c) The discard callback (step c) must exempt *pending completions* (§6.3 pinned: `for D₂ > D_within` is legal); ADR-0004 says only "discard overrun partials." (d) "events behind the wm" — SEMANTICS pins late as `t < wm` (worked example §2.1); an agent reading "behind" as `t ≤ wm` breaks the inclusive-boundary flagship case (egress at exactly 10:05:00.000).

**Cheapest mitigation (one ADR edit + one test, before S1):**
1. Add to ADR-0004: "Admission watermarks are **per-stream singletons owned by ingest**, never derived from an instance's routed subset; the runtime forwards wm advances to every shard as mailbox messages after the events that caused them; `Instance` holds no admission state, only the per-instance clamp, idle floors and virtual floor. `virtualFloor = virtual_now − d`. `idleFloor(sid)` = the construct's max other-input contribution at idle-mark time [or pin another value — but pin one]. The discard step skips pending completions. Late ⇔ `t < wm` strictly."
2. Add one **mandatory conformance case, named in S1's card**: two keys, live driver, `shards ≥ 2`; key A reads then goes silent while key B stays chatty; assert the absence alert for A *fires when stream wm passes the deadline* (fire-time asserted, not just output), and that A's TTL purge happens. This single test makes the misread impossible to ship.

### RC2 — ADR-0005's "Sprint S1" is capacity-impossible as one sprint; the dependency chain through `internal/clock` serializes everything. — Likelihood: HIGH · Impact: HIGH

**Shared assumption:** "Enablers-first is a sequencing statement, so it fits in the first sprint" — ADR-0005 decision 1 literally says "**Sprint S1** builds, in order: the gate, then playback, then the conformance runner."

**Evidence:**
- Playback must run "the real runtime" (ADR-0005 explicitly rejects a test-only engine). The conformance runner "executes every expect block," which needs deploy: full parser (the grammar-differential needs the *whole* grammar — all 23 parse codes), the 34-code validator, lowering, `model` + canonical JSON, `clock`, `partition`, `plan`, runtime skeleton. That is ~7–9 packages plus the gate tooling (`tools.json`, registry, hooks, CI, importcheck, kwgen).
- Capacity: one owner per file (ground rule 17), **≤ 2 agents at once**, lanes ≤ 8 days, sprint ≤ 2 weeks (ground rule 6). Two agents × two weeks cannot produce the gate *and* a full parser *and* the clock *and* playback *and* the runner. Splitting mid-sprint is forbidden (ground rule 6), so the discovery forces either a rules violation or a G0 re-plan.
- Wave parallelism is an illusion for most of Phase 1: `event → model → parser/rule → validate → plan → operators`, with `clock` imported by every operator package, `partition`, `playback` and `runtime` (ARCHITECTURE §3 rules 4–6). Until `clock`'s interface is stable, every operator lane is blocked or building against a moving target; with 2 concurrent agents, the "waves" degenerate into a near-serial chain whose critical path runs through one package with one owner. A clock interface change after operators start costs every lane a rebase.
- ADR-0004's own consequence section admits it: "the clock service is the hardest single package — it gets the most senior review and lands in the earliest sprint." Hardest package, earliest sprint, no named Go specialist yet (sprint model §2: "the first build sprint's plan check names one") — three risk multipliers stacked on sprint one.

**Cheapest mitigation (re-cut at decomposition time, no ADR change needed):** amend ADR-0005's wording from "Sprint S1" to "Stage 1 (sprints S1–S3)" and decompose: **S1** = gate + `event` + `model` + canonical JSON (+ kwgen/importcheck); **S2** = parser + lexer + differential + invalid-corpus tests (self-contained lane, parallel with S1's tail); **S3** = clock (harness ports first, per ADR-0004) + minimal single-shard runtime + playback + conformance runner over *filter/select rules only*, everything else `skip: not-implemented(S<n>)`. Freeze `clock.Instance`'s signature at S3's design gate (G1) before any operator sprint opens.

### RC3 — The slice is an 8–12 sprint phase being carried as "a few sprints"; nothing in the baseline sequences for an early demo-able vertical. — Likelihood: HIGH · Impact: HIGH

**Shared assumption:** "A vertical slice is thin." It was, on 2026-10-30. After the 2026-10-31 amendments it is a horizontal layer cake: four windows + emission/lateness tables, five text-operator families, an attack gallery (≥5 examples × story + timeline + DSL + Go + fixture + citations), two front-ends with byte parity, 57 error codes each with an invalid-corpus test, three sources, three sinks, two binaries, demo kit, metrics, quickstart < 15 min — *and* the enabler stage of RC2.

**Evidence:** count the full-loop semantic sprints implied by ARCHITECTURE §7's traceability table: clock, patterns, windows (likely two sprints: sort/batch vs cron/delay — cron alone owns a tz/DST dialect and a hand-written parser), text, partitions/TTL, ratelimit+emission, connectivity, builder+parity — plus enablers (2–3), plus gallery/demo/docs (2 lighter), plus the release close-out with a whole-engine break-it. That is 11–14 sprints. Each full-loop sprint carries a blind **three-reviewer panel** for semantics (sprint model §6 step 1) and ~6 owner touchpoints. At a realistic 2–3 weeks wall-clock per sprint for a solo owner, Phase 1 is 5–7 months. Nobody wrote a number anywhere; the absence of the number *is* the finding.

**Cheapest mitigation (sequencing + two owner-sanctioned cuts, all within the ratified scope):**
1. **Sequence the kill-switch vertical first**: after RC2's S1–S3, do patterns + partitions + ratelimit + inmemory/log io (S4–S5) so the flagship runs end-to-end in playback by ~sprint 5. Windows, text, http/smtp, gallery follow. An early working demo de-risks morale, review quality and the latency measurement.
2. **Cut `cep fmt` from Phase 1** (owner decision): the formatter (SPEC §8, with "parse → format → parse identical tree" and generated time-clause comments) appears in **no roadmap exit criterion** and in no conformance clause (SPEC's conformance = grammar check, expect outputs, error codes, differential). It is a whole sub-project smuggled in by ARCHITECTURE §3's `cmd/cep validate / test / fmt` line.
3. **Make the attack gallery a trailing lighter-routine sprint** that only *consumes* shipped constructs; cap it at the exit criterion's five examples; pre-write the five stories (doc work, zero engine dependency) in any idle lane now.
4. Pre-agree at decomposition: window sprints **reuse the clock's already-panelled semantics** — one breaker, not a fresh three-reviewer panel, for constructs whose §7 rows the executor already encodes (needs owner sign-off; the sprint model allows the owner to set the routine).

### RC4 — The conformance contract has a hole the first run hits: `expect` blocks cannot populate tables, and the merged log has no table records. The frozen spec's own flagship example is unrunnable. — Likelihood: NEAR-CERTAIN · Impact: MEDIUM-HIGH

**Shared assumption:** "The corpus is executable truth; the conformance runner just runs it." Everyone checked that the expect blocks exist; nobody checked that they can *evaluate*.

**Evidence:** `01-agent-kill-switch.cep` line 29: `resource in SensitiveResources`; its expect blocks (lines 36–42) provide `given` sections for streams only. SPEC §6.8 defines `given` as "one per **input stream**" — no table fixture form exists in the frozen grammar. ADR-0005 §3's merged-log format has event records and punctuations only. Against an empty table the read step's filter is false, the first expect's then-list fails `E-EXP-001`, and the second ("defeat") expect passes vacuously for the wrong reason. Same hole, wider: SEMANTICS §10's byte-identical replay is undefined for any live session whose tables were mutated programmatically mid-run — there is nothing to replay the mutations from.

**Cheapest mitigation (one owner decision now, before S1):** add a spec change-log entry (the freeze allows dated amendments): `given table <Name> [ {row}, … ]` sections in expect blocks, and a `{"table": "<name>", "op": "put|delete", "row": {…}}` record type in the merged-log format with a defined ordering rule relative to events (e.g. applied at its position in file order, visible from the next event — matching §4's snapshot rule). Also pin in ADR-0006 *how* snapshot-per-event reads are synchronized across shards without operator locks (atomic pointer swap to an immutable table version) — the "no locks" rule and a shared mutable table currently contradict each other silently.

### RC5 — "Byte-identical across machines" has three unpinned inputs the ADRs missed: system tzdata, `encoding/json` number decoding, and float/canonical encoding rules. — Likelihood: MEDIUM-HIGH · Impact: HIGH (it attacks the product's headline promise)

**Shared assumption:** "We pinned the toolchain and the Unicode tables, so determinism is handled."

**Evidence:**
- **tzdata:** cron buckets are computed in a mandatory IANA timezone (SEMANTICS §7); Go's `time.LoadLocation` reads the **host OS tz database** unless `time/tzdata` is imported. ADR-0007 pins Unicode tables meticulously; *no document pins tzdata*. Two machines, two tzdata versions (DST rule changes happen yearly), two different byte streams — discovered by the cross-machine clause of ADR-0005 §3 only if CI ever runs on two OSes, which no document requires. (Also: ADR-0009 §3 cites "ADR: windows" for the cron parser — that ADR does not exist; the cron dialect's home is undefined.)
- **JSON numbers:** ADR-0008's `Raw{Attrs map[string]any}` invites the default `encoding/json` decode, which makes every number a float64 — int64 values above 2^53 (snowflake ids, span ids — realistic agent telemetry) are silently corrupted at ingest. Not just a determinism bug: a wrong partition key is a missed detection.
- **Canonical encoding:** ADR-0003/0005 pin "sorted keys, explicit nulls, RFC3339 UTC" but no float formatting rule (shortest-round-trip? `%g`? `-0`? exponent thresholds?), no rule for `+Inf` (float division by zero is not an expression error in IEEE and is unencodable in JSON — emit-time crash), no millisecond-formatting rule for RFC3339 (`.1Z` vs `.100Z`), and no canonical rule for the opaque `object` type's re-encoding.
**Cheapest mitigation:** four lines across two ADRs + one gate row: (1) `import _ "time/tzdata"` mandatory; tzdata version recorded in `cep.BuildInfo()` next to the Unicode version (ADR-0007's pattern, reused). (2) Ingest decodes with `json.Decoder.UseNumber()` and parses against the declared schema type. (3) Canonical JSON pins floats to Go's shortest-round-trip (`strconv.FormatFloat(f,'g',-1,64)`), timestamps to exactly three fractional digits, and defines NaN/±Inf as expression errors per SEMANTICS §10. (4) A T4 gate row runs the conformance suite on a second OS (ubuntu + macos matrix) and diffs output bytes.

### RC6 — The one human is the critical path: ~6 owner gates × ~12 sprints, three ADRs already parked on owner sign-off, and no Go specialist named. — Likelihood: HIGH · Impact: MEDIUM-HIGH (expresses as "late", then as "gates skipped")

**Shared assumption:** "The process protects quality at no schedule cost, because agents do the work." The process is excellent *per sprint*; nobody priced it *times twelve, through one person with a day job*.

**Evidence:** sprint model §4/§6: G0 requires a plan check "answered by the owner: no open question"; G1 owner decisions; G3 owner consent per forwarded blocker; G4 owner's check; §2: the owner "merges every PR by hand"; plus ratification currently pending for the whole baseline and dependency decisions in ADR-0002, ADR-0007, ADR-0009 (incl. the YAML-vs-JSON config pick). Entry criterion G0.1 cannot even be evaluated for the first build sprint until a Go specialist agent is named (§2 roster note). Failure chain: owner latency stretches sprints → pressure to batch sloppily or skip a gate → a skipped gate is exactly where RC1-class bugs pass → trust in the process drops → more skipping. Second-order: the coordinator is "the Claude Code session" — a months-long project's coordination state lives in session memory files; a context loss mid-sprint with no recorded resume point duplicates or orphans lanes.

**Cheapest mitigation:** (1) One ratification session *now* that clears the whole parked queue in a single batch: baseline + ADRs 1–9 + goyacc + x/text + JSON-config + names the Go-specialist agent definition — the model already prefers batched decisions (ground rule 2); schedule it before S1's plan check. (2) Two standing owner slots per week, published in the sprint plan; gates queue to slots instead of interrupting. (3) A written rule in sprint-plan.md: owner latency > N days ⇒ the sprint *pauses* with a recorded resume point (agents stopped, worktrees kept) — making the stall visible and cheap instead of invisible and corrosive. (4) The resume point discipline of §15 is made a G0 entry check (it already exists; make it ticked evidence, not prose).

### RC7 — Grammar drift passes the differential, because corpus-strength accept/reject agreement never compares parse *trees*. — Likelihood: MEDIUM · Impact: HIGH (a rule means different things in spec and engine)

**Shared assumption:** "The differential job is the standing equivalence proof" (ADR-0002 §5 says exactly this).

**Evidence:** the job compares **accept/reject verdicts** over a finite corpus (9 valid examples + 24 invalid files + eval/generated). Three gaps: (1) **Tree-shape divergence on accepted input** — both grammars accept `… and not HumanApprovals[…] for ${kill_window} within ${kill_window}` but if the hand-derived `.y` binds `for`/`within`/`and` with different precedence or associativity than grammar.lark, the engine detects a *different rule* than the normative parse, with both sides green. Zero conflicts on each side proves each grammar is unambiguous *with itself*, not equivalent to the other. (2) **Lexer-level divergence** is outside both the differential's corpus strength and kwgen's protection: kwgen covers only the keyword list; raw triple-quoted strings, duration lexing ("NUMBER + unit tokens assembled by the grammar" — ADR-0002's own note admits this restructures the token stream), BOM, escapes and comment edges live in two hand-written lexers. (3) The corpus has 9 valid files; precedence torture cases are absent by construction (examples are canonical style).

**Cheapest mitigation:** (1) Make the differential compare **shapes, not verdicts**: both sides emit a canonical fully-parenthesized S-expression of the parse (a ~50-line lark tree printer; the Go AST gets a `String()` — cheap because the AST already exists) and the job diffs them per corpus file. (2) Add one precedence/associativity torture file per operator pair to `examples/` (valid, with expect blocks where meaningful). (3) Advisory T4 step: generate N random sentences from grammar.lark (lark can enumerate/generate) and require the Go parser to accept them — catches reject-side drift beyond the corpus.

### RC8 — The per-key model's unexamined seams: cross-stream key typing/encoding, and derived-stream punctuations that no MVP case exercises. — Likelihood: MEDIUM · Impact: MEDIUM-HIGH

**Shared assumption:** "Two streams keyed by `agentId` obviously meet in one instance" — true in the flagship, where both are `string` and spelled identically; not guaranteed by anything in the documents.

**Evidence:**
- Routing is `hash(ruleID, keyValue)` and `instanceKey = ruleID + "\x00" + canonical key encoding` (ADR-0006). Two streams in one block may legally use **different key expressions** (SEMANTICS §9 requires one per stream, nothing requires same type). `Value{TInt,5}`, `Value{TFloat,5.0}` and `Value{TString,"5"}` are the "same" key to an author and three different instances to the encoder — a missed join across streams, i.e. an absence that never defeats and a kill switch firing on an approved action, or never. errors.md has `E-PART-002` (missing key expression) but **no code for cross-stream key type mismatch**, and "canonical key encoding" is specified nowhere (string case? float bits? −0?).
- Single-writer is also quietly broken at two other seams: **shared tables** (covered in RC4's mitigation) and **ingest wm state** (covered in RC1); the third is **derived-stream punctuations**: ADR-0004 §3 makes a downstream rule's contribution "driven by received punctuations" — but a partitioned upstream rule punctuates per *instance*, instances are born and TTL-purged dynamically, and the merge of per-instance punctuations into one derived-stream watermark (a min over a changing set) is undefined. Checked against the corpus: **no example consumes a derived stream** — so this machinery is unexercised surface in the hardest package: built speculatively and untestable, or skipped and a landmine for the first user who chains rules.
**Cheapest mitigation:** (1) Validator rule + new E-code: every key expression in one partition block must have the **same declared type**; specify canonical key encoding in ADR-0006 in five lines (type tag + exact bytes; floats by `math.Float64bits`; reject float keys if cheap — ask the owner). (2) For punctuations, decide smallest-first: either define the merge at the *rule* level (the runtime forwards `Punct{W}` for a derived stream only after all shards finish processing the advance to W — a per-rule barrier, single-threaded trivially in playback), or — cheaper — **defer**: reject rule-consumption of derived streams in v0.1 with a reserved error code (owner decision; SEMANTICS §2.1 stays, the engine just doesn't claim it yet), and delete ADR-0004 §3's obligation from Phase 1's build.

## 4. Inversion check

What would *guarantee* failure: (1) a single point of knowledge — present: one owner, one coordinator session, one clock-package owner; (2) untested-at-scope semantics — present until RC1's two-key live test exists; (3) timeline with no buffer — present: no sprint count or forecast exists anywhere, so every slip is invisible by construction. All three exist today; RC1's test, RC2/RC3's re-cut and RC6's standing slots remove them at a cost of roughly one planning session and three ADR paragraphs.

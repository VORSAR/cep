## Part 2 — New findings

### N1 (blocker). The shard→router handoff edge re-opens the deadlock the revision closed

- **Location:** ADR-0006 §5, second and fourth bullets.
- **Claim:** §5 asserts "a shard goroutine never blocks on anything" and "shards never wait on other shards or sinks, so there is **no cycle in the wait-for graph — deadlock-free by construction**", yet the same section has the shard "hand… the outbox to the **router** … via a **buffered handoff channel**". A buffered Go channel send blocks when full. Counterexample: router blocked sending a derived event into shard S's full mailbox; S finishes an `Advance` and sends its outbox into the full handoff channel; S blocks; S never drains its mailbox; router never completes its send. The wait-for cycle router→S (mailbox), S→router (handoff) is exactly the shape the argument claims impossible — the argument enumerated the shard→sink and shard→shard edges and omitted shard→router.
- **Fix (three sentences, no redesign):** (a) the handoff is a **non-blocking try-send**; on failure the shard retains and merges its outbox and retries; (b) an idle shard parks on `select{ mailbox receive, handoff send of the retained outbox }` so a drained handoff channel wakes it; (c) the router **services handoff channels while blocked on any mailbox send** (select over the pending send + all handoffs). Then every blocking edge points source-ward and the stated argument is actually true. The saturation test should include this exact scenario (full mailbox at the shard whose handoff is pending).

### N2 (blocker). The advance-delivery mechanism is stated two ways, and the slot variant breaks the derived-stream guarantee

- **Location:** ADR-0004 §3 vs ADR-0004 implementation note 2; SEMANTICS §2.1; ADR-0004 §6.
- **Claim:** §3's ordering guarantee rests on FIFO: "control messages and events share the mailbox, so an instance never sees an advance out of order with the events the same source sent before it." The note replaces that with a different mechanism: "enqueueing may replace a not-yet-consumed advance for the same stream in a **shard's pending-control slot (one slot per stream per shard)**." A slot consumed ahead of earlier-enqueued mailbox entries lets an advance **overtake the events that precede it** — in particular the punctuation advance that ADR-0004 §6 requires to *follow* a derived batch ("routes the batch and **then** `ObservePunctuation`") can be applied before the batch is delivered, making the downstream instance judge those events construct-late and drop them. That violates SEMANTICS §2.1: "an event on a derived stream is never behind that stream's watermark by construction — e.g. `delay(D)` releases every held event due in `(W_prev, W]` *before* forwarding `W`, so downstream constructs admit them" — dropped delayed events are missed detections, not a counted race.
- **Fix:** pick FIFO. Advances ride the mailbox in order; coalescing, if kept at all, may only collapse an advance into an **adjacent tail** message for the same stream (nothing between them to overtake). Simplest correct v0.1: no coalescing — advances are already O(events) worst-case and cheap; optimize later with a measurement (ADR-0010's own discipline). State that `CtlDrain` rides the same FIFO.

### N3 (blocker). `internal/event.Value` leaks into the public surface — the SPI is unimplementable outside the module

- **Location:** ADR-0008 §1 (`type Raw struct { Values []event.Value; Batch string }` — "mapper output, ALREADY schema-aligned"); ADR-0012 note (`cep.InputHandler … SendRaw(attrs []event.Value, ts int64) error`); ADR-0012 §5 (`cep.Table` rows, type unstated).
- **Claim:** Round 1's `Raw{Attrs map[string]any}` was externally constructible; the perf-driven revision made `Raw` carry `[]event.Value` — an `internal/` type that code outside `github.com/vorsar/complex-events-engine` **cannot import, name, or construct**. A third-party `Source` must call `emit(cepio.Raw)` and a third-party `Mapper` must return `Raw`; both are now impossible outside this repo, which defeats the SPI's stated purpose ("sibling-repo adapters implement exactly the three Phase-1 interfaces" — ARCHITECTURE View 4; decision #10) and `SendRaw` is equally unusable by embedders. This is a broken contract at the system's one extension boundary.
- **Fix:** define the public value boundary once and reuse it in all three places: either a public `cep.Value` (thin alias/struct mirroring `event.Value`, converted at the facade — costs one copy at ingest, which ADR-0010 can budget) or, better for the zero-alloc goal, a **schema-bound builder** handed to mappers/sources (`cepio.RowWriter` with typed setters `SetString(attr int, v string)` etc., writing directly into the engine-owned `[]event.Value`). Pick one; apply to `Raw`, `SendRaw`, and `Table` rows.

### N4 (should-fix). Ingest/router goroutine cardinality is stated three ways

- **Location:** ADR-0006 §4 ("sources deliver to **an ingest goroutine per source**") vs ADR-0004 §1 ("The registry is **written only by the ingest goroutine** (live)") vs ADR-0012 note ("the router is the **ONLY** writer to shard mailboxes and sink queues") vs View 2 (one `ING` box; `RTR` "(ingest side)").
- **Claim:** With per-source ingest goroutines, the `StreamRegistry`, the routing tables, and the mailbox-write monopoly all acquire multiple writers — races the single-writer design just bought its correctness with ("Seq (per-stream atomic counter)" in ADR-0006 §4 is a fossil of the multi-writer reading). Pin the topology: one ingest/router goroutine per runtime (sources' thread-safe `emit` feeds its queue — this is what View 2 draws), or per app with per-app registries; update ADR-0006 §4 accordingly.

### N6 (should-fix). The new diagrams contradict the revised prose they were added to illustrate

- **Location:** ARCHITECTURE §2a layer diagram; §5a View 1.
- **Claim:** The owner's elegance directive makes the diagrams normative-adjacent, and agents copy them. (a) The §2a diagram has **no edge into `internal/parser`** (nothing may call it as drawn), omits `cep → validate/plan` (how Deploy runs its pipeline), `pattern/window → expr`, `expr → text/table`, `validate → window`, and any `metrics` edge. (b) View 1 draws `INST → PAT`/`INST → WIN` — the exact partition→operator edges F1 just removed (ADR-0006 §2: the planner constructs `Op`; partition imports "event and clock ONLY") — and `PAT & WIN → TXT & TBL`, which rule 5 forbids (text/table access is through compiled `expr` nodes, ADR-0011 §5). ### N7 (should-fix). Drain barrier: quiescence is under-specified for derived chains

- **Location:** ADR-0012 §3 Stop; implementation note (`CtlDrain` + outbox ack).
- **Claim:** Stop "wait[s] for shard outboxes and sink queues to flush" — shard **mailboxes** are missing from the wait condition, and the barrier itself creates the traffic that fills them: advancing contributions to `upTo` fires due completions, whose emissions are routed as derived events to *other* shards, possibly after those shards already acked their own barrier. A single ack round plus outbox/queue flush can therefore return with re-ingested events still unprocessed in mailboxes (silently lost, uncounted). Fix: define quiescence as a fixpoint — all mailboxes empty ∧ all outboxes handed off ∧ sink queues flushed — or run the barrier per topological level of the stream DAG (depth is statically known from the StreamNode graph); either is a one-paragraph protocol.

### N8 (should-fix). The zero-alloc gate as written is unsatisfiable on the flagship's own hot path

- **Location:** ADR-0010 §1 ("steady-state hot path allocates **zero** per event — … filter/pattern/window evaluation … A T2 gate row runs `testing.AllocsPerRun` benchmarks per stage and fails on > 0") vs ADR-0013 §2/§5 and ADR-0010 §4.
- **Claim:** `every`-spawning allocates per qualifying event (a `partial` + its `captures []event.Event`, len = positive step count), and the kill-switch's step 0 (`every read = AgentActions[action == 'read' …]`) qualifies on every sensitive read — spawn is per-event work, not per-match work, and pooling partials was not sanctioned (ADR-0010 §4 rejects event pooling; ADR-0013 consequences: "capture slices copy events (no pooling)"). As written, the pattern-stage alloc benchmark is structurally red on the flagship, which is exactly the pressure toward gate-cheating the design-quality bar forbids. Fix: name the spawn path (like match emission) as a budgeted, tripwire-tracked allocation — or sanction a per-instance partial freelist (single-threaded per key, so deterministic and safe, unlike cross-key event pooling). Decide; don't let the gate discover it.

## Part 3 — Elegance pass (owner directive)

Criteria applied as given: one home per concept; no charter cheats; minimal interfaces owned by the right layer; no mechanism where a simpler one satisfies the binding requirements; diagrams faithful to prose.

### Verdicts per area

- **Component layout — acceptable-with-note.** Expressions, fan-out, time, per-key state, and lifecycle each now have exactly one home (expr / StreamNode / clock two-level / partition.Instance / AppHandle), and the Siddhi study visibly disciplined the shapes (adopt the junction concept, reject its sync delivery; adopt compiled executors, reject the instanceof builder). Three concepts still have no home: the formatter (F10), the metrics/health endpoint (F16), the demo kit + attack gallery (F17). Note: `internal/ratelimit` is now a near-empty package (one anchor comparison; its state lives in `partition.Instance`, its invocation in the emission path) — either give it the whole §8 emission-policy concept or fold it and say so; a package that owns one `if` is layout noise.
- **Interfaces — acceptable-with-note.** `StreamRegistry`/`Instance`/`AdvanceCallbacks` is a clean two-owner time contract; `OpState` solved F1 with structural satisfaction instead of an import (genuinely elegant); `window.Kind` + `Out` keeps emit-mode routing in plan; `Expr`/`Row` is minimal and allocation-honest. Two deductions: the public boundary leaks an internal type (N3 — ownership of the value type is simply on the wrong side of the fence), and the snapshot seam has two names (`Walkable` vs `OpState`, N6c).
- **Layering — acceptable-with-note.** The L0–L5 charter is real, the single L2 exception (expr) is argued and bounded, and the three dependency-inversion seams are correctly owned low. The cheats are textual, not structural: a dangling "rule ARCH-3" authorization for same-layer imports, two unauthorized same-layer edges in actual use (`cep → parser`, `cep → playback` for the expect sandbox), and ADR-0001 §4 enforcing last round's rules (N5). Fix the text and this layer model is the genuinely elegant piece of the baseline.
- **Concurrency model — inelegant (as written); the spine is right.** Single-writer-per-structure (registry: ingest; mailboxes/queues: router; instance: shard) with "only the router blocks" is the correct, lintable discipline — but three mechanisms are unreconciled in the text: handoff blocking semantics contradict the never-blocks rule and void the deadlock proof (N1), advance delivery is specified as both FIFO and slot-replacement with different correctness (N2), and the ingest goroutine cardinality is stated three ways (N4). The specific fix: one **wait-discipline table** in ADR-0006 (every goroutine class × what it may wait on), a FIFO-only control channel, one ingest/router goroutine — after which the "deadlock-free by construction" sentence becomes true and the model is elegant.
- **I/O streams — inelegant until N3 lands.** Schema-driven decode straight into typed slots (one pass, full-range int64, differential-tested + fuzzed) and router-written bounded sink queues with coalescing flushers are the right mechanisms, each justified by a measured citation rather than fashion. But the SPI — the one boundary outsiders touch — is currently unimplementable outside the module (N3), and that is the opposite of the "small public SPI" the whole connectivity story is built on. Specific fix in N3; after it, this area is elegant.
- **Plugin seams — acceptable-with-note.** View 4's honesty (three real interfaces, "experimental" tag, reserved seams *named but not opened*: function SPI, window-kind SPI, llm: provider, snapshot encoder) is exactly right, and the expr `Registry` doubling as the future FA11 surface means the extension model already exists internally before it is promised externally. Contingent on N3; and the `Mapper`/`Source` docs must state the construction path for `Raw` once N3 picks it.

### Tactical-looking survivals (named, per the directive)

1. The **slot-replacement coalescing** in ADR-0004's note — a micro-optimization that contradicts the ordering guarantee four paragraphs above it and SEMANTICS §2.1 (N2). This is precisely "a mechanism for which a simpler one (FIFO) satisfies the binding requirements."
2. The **zero-alloc gate row** that the flagship's spawn path cannot pass (N8) — a rule that cannot be obeyed invites the suppression culture DEVELOPMENT.md forbids.
3. ADR-0014's **unedited draft sentence** ("…validate imports it downward? NO — …") in a normative decision — thinking-out-loud shipped as law (N5.5).
4. ARCHITECTURE §5 step 2's **garbled E-NAME-001 parenthetical** (F23), now survived two rounds verbatim.
5. View 1 drawing the **pre-F1 edges** the revision just abolished (N6) — the diagram of the old design attached to the new one.
6. Honorable mention, not a violation: the outbox's "unbounded-but-accounted" with a 65,536-emission tripwire is a guarded compromise, but it is labeled as such, metered, and bounded by one `Advance` — acceptable as decided.

### What is genuinely good (one line, for calibration against the bar)

The two-level clock with delivered advances, structural `OpState`, completion-as-timers (ADR-0013 §3 making the §6.3 pending-completion pin hold *by construction*), batch-size-invariance as a conformance property, the anti-Siddhi purge test derived from a first-hand-verified defect, and the three-tension resolution in ADR-0010 are architecture earning its keep, not ceremony.

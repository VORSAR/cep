# Prior art: siddhi-core internal architecture (owner-directed study, 2026-11-01)

> **Historical — prior-art study, 2026-11-01; evidence only.** What was adopted is in [ARCHITECTURE.md](../ARCHITECTURE.md) and the ADRs it names in §11 (StreamNode: [ADR-0012](../adr/ADR-0012-streamnode-and-app-lifecycle.md)).

Commissioned because the owner judged Siddhi "sufficiently well written" architecturally. Source: /Users/ramith/code/siddhi @ 98de1eb41 (v5.1.35-1), module siddhi-core. Mapping produced by a thorough sweep (agent `siddhi-core-arch`); two load-bearing claims verified first-hand by the coordinator (the fc771aab8 "remove cloning" commit; the per-event purge-scheduling defect in `PartitionRuntimeImpl.initPartition()` — confirmed by reading the Java). §1–§10 are the map; §11 is our adopt/adapt/reject digestion feeding the Phase 1 baseline revision.

## 1. Packages and dependencies
- `config`: three context levels — `SiddhiContext` (per manager: extension map, persistence/error stores, data sources), `SiddhiAppContext` (per app: thread pools, ThreadBarrier, TimestampGenerator, SnapshotService, playback flag, static ThreadLocals PARTITION_KEY/GROUP_BY_KEY), `SiddhiQueryContext` (per query: name, partitionId, generateStateHolder()).
- `event`: ComplexEvent/StreamEvent/StateEvent, compile-time Meta* layouts, converters, cloners, factories.
- `executor` (165 files): expression-tree nodes (condition/compare, math, function, incremental).
- `query` (138 files): QueryRuntimeImpl; input receivers (single/join/state); processor/ (Processor, filter, window, function); selector/ (QuerySelector); output/ (callbacks, rate limiters); store-query runtimes.
- `stream` (39 files): StreamJunction; input/ (InputManager, InputHandler, InputEntryValve, InputDistributor, sources); output/ (StreamCallback, sinks).
- `partition` (8), `table`, `window` (named shared windows only), `aggregation` (IncrementalExecutor chain per time unit), `trigger`, `debugger`, `function`, `exception`.
- `util` (175 files) is a catch-all holding the COMPILER (`util/parser/*`: SiddhiAppParser, QueryParser, ExpressionParser, input-stream parsers, SelectorParser, OutputParser, PartitionParser, OperatorParser) plus Scheduler, ThreadBarrier, snapshot/, persistence/, extension loading, locks, timestamps, error handling.
- Measured dependencies: `event` nearly a leaf (imports util + one partition touch from cloners); `executor` imports event/config/util; `query` imports everything (event 425, util 339, executor 89); **`util` imports back into executor (182), event (177), query (155) — `query` and `util` are mutually dependent. No layering is enforced**; de facto flow: query-api AST → util.parser (compiler) → runtime objects → event/executor primitives.

## 2. Processing pipeline
- `query.processor.Processor`: `process(ComplexEventChunk)`, `process(List<ComplexEventChunk>)`, get/setNextProcessor, setToLast — a singly linked chain pushed synchronously. `SchedulingProcessor` adds get/setScheduler. `ProcessingMode` (BATCH, SLIDE, HOP, GROUP, RESET) combined across the chain informs aggregator expiry.
- Chain order: StreamJunction → ProcessStreamReceiver (implements StreamJunction.Receiver; copies events in via StreamEventConverter, takes the query LockWrapper, debugger/latency hooks) → FilterProcessor/stream functions → EntryValveProcessor (inserted before first SchedulingProcessor) → window processors → QuerySelector (projection/group/having/order/limit; a Processor) → OutputRateLimiter (NOT a Processor; typed setNextProcessor overload; PassThrough/event/time/snapshot variants) → sendToCallBacks → QueryCallbacks + one OutputCallback (InsertIntoStream/Table/Window, Update/Delete/UpdateOrInsert, *EndPartition variants).
- Assembly in `util.parser.QueryParser.parse()`: InputStreamParser → StreamRuntime (Single/Join/State); SelectorParser; lock selection (LockSynchronizer syncs join locks over named windows); OutputParser (rate limiter + output callback); QueryParserHelper.initStreamRuntime; QueryRuntimeImpl ctor wires selector → rate limiter; streamRuntime.setCommonProcessor(selector) appends selector to chain; SingleInputStreamParser builds the per-stream processor list.
- Joins: JoinStreamRuntime = two SingleStreamRuntimes each ending in a JoinProcessor that queries the other side's FindableProcessor through a CompiledCondition, emitting StateEvents.
- Patterns/sequences: StateStreamRuntime holds a tree of InnerStateRuntimes (Stream/Next/Every/Logical/Count) built from Pre/PostStateProcessor pairs; MultiProcessStreamReceiver collects results in a static ThreadLocal ReturnEventHolder and calls outputRateLimiter.sendToCallBacks directly.
- SiddhiAppRuntimeBuilder.addQuery subscribes receivers to junctions; InsertIntoStreamCallback.init creates the output junction if the stream was never declared.

## 3. StreamJunction (stream decoupling)
One junction per stream id (streamJunctionMap; partitions hold separate maps for #inner streams). Inner interface Receiver; inner class Publisher implements InputProcessor (wraps sends in try/catch → handleError). Publishers: InputHandler path, sources, triggers, InsertIntoStreamCallback (insert-into feedback), Window.setPublisher, fault streams. Subscribers: ProcessStreamReceivers (one per query input), StreamCallbacks, sinks, PartitionStreamReceiver, aggregation receivers.
- **Sync mode (default): depth-first on the publisher's thread** — all receivers get the same event object and copy on receipt.
- **Async mode** (@Async(buffer.size, workers, max.batch.size)): an LMAX **Disruptor** per junction, built in startProcessing(); StreamHandler batches to receivers; with workers > 1 every handler sees every slot and claims via CAS (getAndSetIsProcessed) — **ordering across workers is lost**. @Async at app level rejected.
- Errors: @OnError(action=LOG|STREAM|STORE); STREAM → `!stream` fault junction via FaultStreamEventConverter; STORE → ErrorStore.

## 4. Event model
- ComplexEvent: intrusive `next` pointer, timestamp, outputData, type (CURRENT/EXPIRED/TIMER/RESET), getAttribute(int[] position).
- StreamEvent: three arrays (beforeWindow, onAfterWindow, output); **MetaStreamEvent lays them out at compile time so only used attributes are carried**.
- StateEvent: StreamEvent[] (one chain per pattern/join slot; linked list for counted matches) + output + id. Positions are int[]{chainIndex, indexInChain, attrType, attrIndex} (SiddhiConstants). GroupedComplexEvent for group-by output.
- ComplexEventChunk<E>: first/last/cursor wrapper over the intrusive list (insertBeforeCurrent/remove/detach, isBatch flag) — not a collection.
- **No pooling anymore**: Stream/StateEventFactory.newInstance() just calls `new` (names are Disruptor-EventFactory leftovers). Copying via Stream/StateEventCloner and Zero/Simple/Selective converters.

## 5. Expressions
`executor.ExpressionExecutor`: `Object execute(ComplexEvent)` + `getReturnType()` only (Siddhi 4's cloneExecutor removed). Interpreted tree: VariableExpressionExecutor (position reads) and ConstantExpressionExecutor leaves; And/Or/Not; one class per type-pair for compare/math (EqualCompareConditionExpressionExecutorBoolBool, AddExpressionExecutorInt, …); FunctionExecutor (extensions, may hold state); AttributeAggregatorExecutor; InConditionExpressionExecutor (table lookup). Built by `util.parser.ExpressionParser.parseExpression(...)` — a 1,583-line instanceof chain taking (Expression, MetaComplexEvent, currentState, tableMap, out-list of variable executors, groupBy, defaultStreamEventIndex, ProcessingMode, outputExpectsExpiredEvents, SiddhiQueryContext); variable positions patched later by QueryParserHelper.updateVariablePosition. Function resolution order: script → FunctionExecutor extension → aggregator fallback.

## 6. Time
- `util.timestamp.TimestampGenerator` (currentTime, setCurrentTimestamp, addTimeChangeListener, idle/increment), one impl: wall clock normally; **in playback returns last event timestamp, never retreats, notifies listeners synchronously**; TimeInjector heartbeat advances by `increment` after `idle.time` of no input.
- Playback on via @app:playback or enablePlayBack(); InputHandler.send(ts, …) sets event time before dispatch, **so timers due ≤ ts fire first, on the caller's thread**.
- `util.Scheduler`: one per SchedulingProcessor (SchedulerParser), target = the EntryValveProcessor. notifyAt(t) queues per-partition/group-key state (SchedulerState in a StateHolder). Live: ScheduledExecutorService. Playback: time-change listener collects due states, sorts (TreeMultimap), fires. Firing builds a TIMER StreamEvent, takes query lock + ThreadBarrier.enter, restores partition ThreadLocal, pushes into EntryValve onward (window expiry etc.). **Processors before the valve (filters) never see timer events.** Cron windows/triggers use Quartz (CronSchedulerUtil).

## 7. Partitions
- **Query runtimes are NOT cloned per key** (removed in fc771aab8, 2019 — verified). One QueryRuntimeImpl per partitioned query (PartitionParser → QueryParser with partitionId).
- PartitionStreamReceiver subscribes to the outer junction, computes the key (Value/RangePartitionExecutor), calls SiddhiAppContext.startPartitionFlow(key) (ThreadLocal), PartitionRuntimeImpl.initPartition(), then publishes into a shared inner junction — **inner junctions are always sync, which is what keeps the ThreadLocal valid**. Events with no key are sent once per known key.
- Isolation lives in STATE, not structure: SiddhiQueryContext.generateStateHolder() → PartitionStateHolder/PartitionSyncStateHolder (map partitionKey → groupByKey → State via the ThreadLocals) when partitioned/grouped, else SingleStateHolder. Group-by rides the same mechanism (QuerySelector sets GROUP_BY_KEY). InsertIntoStreamEndPartitionCallback clears the flow on the way out.
- Purge: @purge(enable, interval, idle.period); PartitionState maps key → last seen; periodic task removes idle keys and cleanGroupByStates() on every registered holder; States self-remove on returnState when canDestroy().
- **Defect (verified):** in initPartition() the scheduleWithFixedDelay purge task sits OUTSIDE the new-key branch — with @purge enabled, every partitioned event schedules another periodic task.

## 8. State and snapshots
No Snapshotable interface anymore. Each component defines a State subclass (`util.snapshot.state.State`: snapshot(), restore(Map), canDestroy()) + StateFactory, held in a StateHolder<S> (getState/returnState/getAllStates/cleanGroupByStates); generateStateHolder auto-registers in SnapshotService under partitionId → queryName → "id-name". Users: AbstractStreamProcessor (windows), FunctionExecutor, aggregators, OutputRateLimiter, Scheduler, StreamPreStateProcessor, PartitionRuntimeImpl. SnapshotService.fullSnapshot/incrementalSnapshot/restore: threadBarrier.lock() (blocks entry at InputEntryValve, EntryValveProcessor, Scheduler), waitForSystemStabilization (≤100×1s sleeps, then proceeds SILENTLY), walks partitionId → query → element → "partitionKey--groupByKey" → State.snapshot(), ByteSerializer. Granularity: element × partition key × group-by key; Snapshot-implementing values (SnapshotableStreamEventQueue) do base + incremental op logs. Async Disruptor buffers are NOT in snapshots.

## 9. Lifecycle
- SiddhiManager: shared SiddhiContext + ConcurrentMap name → runtime; createSiddhiAppRuntime = SiddhiCompiler → SiddhiAppParser.parse → SiddhiAppRuntimeBuilder.build(); sandbox variant strips sources/sinks/stores; shutdown/persist/restore loop all apps; apps interconnect only via InMemoryBroker.
- Parse order: app annotations → context services (ThreadBarrier, cached pool, scheduled pool of 5, TimestampGenerator, SnapshotService) → streams (incl. fault) → tables/windows/functions/aggregations → queries & partitions in declaration order → triggers.
- start(): startWithoutSources() then startSources(). startWithoutSources order: ExternalReferencedHolders → sinks connect (retry) → tables connect (retry) → junctions start (Disruptors) → aggregation purging → triggers → inputManager.connect().
- shutdown() order: sources → tables → sinks → tables AGAIN → ExternalReferencedHolders → triggers → inputManager.disconnect() → "Shutdown-Cleaner" thread: sleep 1s, stop junctions, sleep 1s, shutdownNow pools.
- `stream.input.InputHandler` is the app-facing ingest API (send(Object[]) / send(ts, …) / send(Event[])); path: InputEntryValve (barrier) → InputDistributor → StreamJunction.Publisher.

## 10. Elegant vs ugly (as found)
Elegant: compile-time Meta layouts with int[] positions; ONE extension model for everything (@Extension + ClassIndex/OSGi discovery → SiddhiContext map "ns:name" → typed ExtensionHolder filter → SiddhiClassLoader; built-ins like window:time ride the same path; @Parameter metadata drives validation and docs); StateHolder+ThreadLocal keys unify partitioning, group-by and snapshots; ThreadBarrier as a cheap quiesce point.
Ugly: compiler in `util` and query↔util mutual dependency (no enforced layering); implicit context via static ThreadLocals (PARTITION_KEY, GROUP_BY_KEY, multiProcessReturn, skipStateStorage, SelectorParser.containsAggregatorThreadLocal) — breaks across async boundaries; split lock discipline (receiver locks, OutputRateLimiter unlocks before callbacks, double-unlock path guarded only by isHeldByCurrentThread); sync-mode fault propagation skips receivers k+1..n and unwinds to the publisher; Scheduler only logs timer errors; shutdown relies on sleeps and stops tables twice; @app:enforceOrder parsed but never read; stale comments.

## 11. Adopt / adapt / reject — the digestion feeding our baseline revision

| Siddhi concept | Verdict | Our counterpart and the reasoning |
|---|---|---|
| StreamJunction (one hub per stream; publishers/subscribers; insert-into feeds a junction) | **ADAPT** | New ADR: a `StreamNode` in `internal/plan` per declared or derived stream — the single place fan-out, multi-consumer delivery and derived-stream re-ingestion are defined (fixes arch-review F4's undesigned re-ingestion). We keep the CONCEPT (stream as first-class hub) but reject depth-first-on-caller-thread delivery: routing goes through the shard mailboxes per our concurrency model, and ordering is per key, never per junction. |
| Compile-time Meta layouts + int[] attribute positions | **ADOPT** | `internal/plan` compiles every attribute reference to (streamSlot, attrIndex) against the schema; operators never look up by name at runtime. Matches our index-aligned `event.Value` slice; extends it to pattern StateEvent-style capture slots. |
| ExpressionExecutor tree (execute(event) nodes; typed leaf/compare/math nodes) | **ADOPT (shape), simplify (Go)** | New ADR-0011 `internal/expr`: compiled executor tree `Eval(ctx, row) (event.Value, error)`; per-type node specialization where it pays (int/float compare), one generic node elsewhere; built by `internal/plan` from the model — never a 1,583-line instanceof chain: table-driven dispatch keyed by (op, type) pairs. Fixes arch-review F6 (no expression owner). |
| Processor chain with setNextProcessor | **ADAPT** | Our plan graph wires operator NODES explicitly instead of intrusive next-pointers; uniform `operator.Node` interface with `OnEvents(batch)` / `OnTimer(due)` callbacks (chunk-based, see next row). Explicit graph beats hidden linked lists for review and for the import DAG. |
| ComplexEventChunk (batch amortization through the chain) | **ADOPT** | Operators process `[]event.Event` batches end-to-end (ingest batches, timer batches). This is also the Disruptor lesson (batch effect) ahead of the perf study; the chunk is a slice, not an intrusive list (Go GC favors slices; no pooling by default — Siddhi itself abandoned pooling, a data point for ADR-0010). |
| TimestampGenerator + Scheduler + EntryValve (centralized time; playback = timers fire on send; timer events enter AFTER filters) | **ADOPT (already convergent)** | Validates ADR-0004's single clock service. We additionally adopt the explicit rule "timer work enters the operator graph at a defined valve point, never through filters" — our clock Advance callbacks deliver (a) released events to the graph head, (b) timer firings directly to the owning operator node, never through filters. |
| Partition isolation via StateHolder maps + ThreadLocal flow keys | **REJECT mechanism, keep granularity** | ThreadLocal implicit context is on our forbidden list (no globals; breaks under async — Siddhi's own ugly list). Our isolation is structural: `partition.Instance` per (rule, key) on one shard. We DO adopt the granularity lesson: state keyed by partition key × (future group-by key) with one uniform mechanism — Instance owns a keyed sub-state map when group-by arrives (P2), not a second mechanism. |
| Runtimes not cloned per key (state-only partitioning, post-fc771aab8) | **ADOPT** | Confirms our design: one compiled graph per rule; per-key state only in Instance. Cheap keys, no per-key object graphs. |
| @purge per-event scheduling defect (verified) | **LESSON** | TTL purge is a clock timer per instance (ADR-0006), scheduled exactly once at instance birth, re-armed on activity — a conformance case asserts one timer per instance (the anti-Siddhi-bug test). |
| @Async Disruptor per junction; workers>1 loses ordering | **REJECT (for MVP), LESSON** | Our ordering guarantee is per key via shard serialization; we never offer an "async stream" knob that silently drops ordering. Perf ADR may adopt a ring buffer INSIDE the mailbox seam later — behind the interface, without a semantics knob. |
| One extension model for everything (@Extension discovery, typed holders, parameter metadata driving validation+docs) | **ADOPT (Phase 5 shape, named now)** | Our closed catalogs (functions, windows, sources/sinks) become ONE registry shape in `internal/plan`: name → descriptor {kind, signature, factory}; built-ins register through it from day one so the FA11 SPI is the same mechanism opened up later — Siddhi's strongest proof that built-ins and extensions must share one path. |
| State/StateFactory/StateHolder + SnapshotService walking registered holders; ThreadBarrier quiesce; silent stabilization timeout | **ADAPT** | Phase-2 seam: our `partition.Walkable` widens (arch-review F19) to a registry the runtime owns — every stateful component registers its state at plan time (Siddhi's auto-registration lesson); quiesce = stop-the-shards barrier (natural in our mailbox model, no sleeps); we reject the silent-timeout-then-proceed (a correctness engine never snapshots "probably quiesced"). |
| Lifecycle: startWithoutSources→startSources; ordered teardown; InputHandler façade; SiddhiManager multi-app | **ADOPT (ordering), fix (shutdown)** | New ADR-0012: `cep.Runtime` holds many apps (roadmap FA1 core); bring-up = plan → connect sinks → connect tables → start shards → start sources; teardown = stop sources → drain shards to a watermark barrier → flush sinks → stop (context-deadline based, NO sleeps, tables stopped once). `cep.App.Input(stream)` is our InputHandler analog. |
| Fault propagation in sync junctions (skip remaining receivers, unwind to publisher) | **REJECT** | Our per-rule error scoping (SEMANTICS §10) is already stronger; delivery to N consumers is independent per consumer queue — one rule's panic cannot skip another's delivery (panic in operator = recover at shard boundary, per-rule error, counted). |
| Quartz for cron | **REJECT** | ADR-0009 already pins the in-repo 5-field parser; Siddhi's Quartz pull is exactly the dependency weight we avoid. |

**Net effect on the revision:** Siddhi's strengths map to five concrete changes (StreamNode ADR, expr ADR shape, chunked operator interface, one-registry extension shape, lifecycle ADR), and its documented weaknesses become five of our MUST-NOTs (no ThreadLocal context, no depth-first cross-rule delivery, no silent quiesce, no sleep-based shutdown, no ordering-losing async knob) — each now citable to observed consequences in the reference implementation rather than taste.

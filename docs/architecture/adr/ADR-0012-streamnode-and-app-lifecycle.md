# ADR-0012: StreamNode (the junction, adapted) and the multi-app runtime lifecycle

## Status
Accepted (owner, 2026-11-01 — conditions in ADR-0015/qa-strategy.md; added 2026-11-01; closes architect review F4's undesigned derived-stream re-ingestion and F13's foreclosed multi-app requirement; adapts siddhi-core's StreamJunction and SiddhiManager lessons — study §3/§9/§11).

## Context
Streams need one first-class home: multiple rules consume one stream; a rule's output stream may feed other rules (DAG, single producer — SPEC §3.3 as fixed in the L6 round) and/or sinks; sources publish into declared streams. Siddhi's StreamJunction proves the concept; its depth-first-on-caller-thread delivery contradicts our per-key serial model and is rejected. Roadmap FA1 lists **multiple apps per runtime** as core; the original baseline's bare ints foreclosed it (F13).

## Decision
1. **`plan.StreamNode`** — one per declared or derived stream per app: `{AppID, StreamID, Schema, TimeClause|nil, Producer (source-binding | ruleID), Consumers []ConsumerRef, SinkBindings []SinkRef, Punctuates bool}`. The planner builds the full stream graph *(annotated 2026-11-02: the graph CHECKS below — E-GRAPH-001/002/003 and the derived-stream rejection — run in `internal/validate`, which owns the error catalog, during sprint S2.2b — together with the cross-stream partition-key type check; the planner consumes the already-validated graph)*, validates DAG/single-producer/source-xor-derived (E-GRAPH-001/002/003), **and rejects any rule that consumes a derived stream — v0.1 restriction, owner decision 2026-11-01 (ADR-0004 §6; the code is assigned in the spec rev-3 batch at S1's plan check): a derived stream's `Consumers` list may hold sinks and tables only** — and hands the **router** a compiled routing table: `StreamKey → [(ruleID, keyExpr, shardFn)] + [sinkQueueIDs]`. All fan-out knowledge lives here; shards and operators know nothing about consumers. *(Annotated 2026-11-06, S3.2b-1 as built: the planner's output is `plan.App{Streams, Tables, Rules}`; each rule carries its inputs and its key attribute per input (`plan.Rule.KeyAttr`), which the router reads. There is no `StreamNode`, `AppID`, sink binding or key `Expr` yet; the facade and the sinks come with S3.3 and S5.)*
2. **Identity (the F13 fix):** every runtime-internal id is scoped — `AppID` (dense int per deployed app) + per-app `StreamID`/`RuleID` ints; the composite `StreamKey{App, Stream}` is what routing tables key on. `cep.Runtime` holds N independent apps: separate models, stream graphs, registries, instances; **no cross-app streams in v0.1** (an app's rules may reference only its own streams; cross-app wiring = the host program moving events through the public API, or Phase-5 features).
3. **Lifecycle (Siddhi's ordering adopted; its sleeps rejected):**
   - `Deploy(src) (AppHandle, error)`: parse → validate → plan → expect-sandbox (ADR-0005 §4; **one fresh ephemeral sandbox per expect block** — tables start empty, `given table` rows seeded via table-load records prepended to the block's log, through the internal load path, never the public `Table` API: the sandbox never runs `Start` — SPEC §6.8 rev 2, consistency review B2) → **register** (inactive).
   - `AppHandle.Start(ctx)`: connect sinks (retry) → load/connect tables → start shard delivery for the app's instances → start sources LAST.
   - *(Annotated 2026-11-06, S3.2b-2 (owner, [decisions](../../sprints/decisions.md#owner-decisions-2026-11-06--s32b-2s-review-and-break-it), decision 1): with a recording, the drain also waits for its stop line — only until the stop's deadline; past it, every alert being out, the recording is marked failed and the stop succeeds.)*
   - `AppHandle.Stop(ctx)`: stop sources FIRST → inject a **drain barrier**: advance every app stream's contribution to the max observed event time (not +∞ — pending absence timers whose deadlines haven't been reached are NOT fired early; they are simply left unfired, honestly dropped with a counted `drained_pending` metric) → wait for **quiescence as a fixpoint** (round-2 N7): all shard mailboxes empty ∧ all outboxes handed off ∧ all sink queues flushed — re-checked after each round because barrier-fired completions add outbox and sink-queue work (and, from Phase 2, re-ingest derived events — in v0.1 no rule consumes a derived stream, ADR-0004 §6, so one extra round suffices in practice; the fixpoint loop stays, so Phase 2 needs no change); the fixpoint terminates because the stream DAG has finite depth and the barrier adds no new event times. *(Annotated owner, 2026-11-05, S3.2a-1 D1, D3 ([decisions](../../sprints/decisions.md#owner-decisions-2026-11-05--s32a-1s-design-after-the-architecture-review)): under D1 the barrier raises every contribution to one past the max observed event time (`clock.StreamRegistry.Drain`), so that last instant — complete once the sources are stopped — finalizes, and any deadline after it stays unfired. A recording ends with a stop record that replays this drain.)* *(Annotated owner, 2026-11-05, S3.2a-2 F5, F2 ([decisions](../../sprints/decisions.md#owner-decisions-2026-11-05--s32a-2s-design-after-the-architecture-review); design [s3-2a-2-design.md](../../sprints/s3-2a-2-design.md) §5): the barrier's mechanism is `internal/runtime`'s `Drain`, which `Stop` wraps. A drain **ends the app's input**: by intake order, no later event, tick or table write of the app reaches its shards, and the runtime refuses them. Ticks continue for other apps. Every shard acks through its outbox, and a flush marker follows the app's outputs through each sink queue. `drained_pending` counts the body timers left unfired, TTL timers excepted.)* All bounded by `ctx`'s deadline → detach. No sleeps anywhere; every wait is on a state with a deadline (testing.md rule 1 applied to production code). *(Annotated owner, 2026-11-04, S3.1-1; [decisions](../../sprints/decisions.md#owner-decisions-2026-11-04--s31-1s-clock-after-two-architecture-reviews), D3: wall ticks now move quiet streams; at Stop the ticks stop BEFORE the sources, so a shutdown never fabricates an absence (S3.2a builds the ticks; S4.2's drain test covers an already-quiet stream).)*
   - `Undeploy` = Stop + unregister; `Runtime.Close(ctx)` = Stop all apps in reverse deploy order, then stop shards. *(Annotated 2026-11-07, S3.3-1 ([design](../../sprints/s3-3-1-design.md) §2, §3.5, §3.7; owner, [decisions](../../sprints/decisions.md#owner-decisions-2026-11-07--s33-1s-design-after-the-panel), 1): as built, `Deploy(ctx, name, src, opts…) (*AppHandle, error)`; a stopped app stays stopped — `Start` after `Stop` is `ErrStopped`, a restart is a new `Deploy` (annotates S3.2a-2's F5); a per-app stop quiets the app's ticks before cancelling its sources (D3 above); the tables' starting rows come from `WithTableRows`, written at `Start` after the recording's header and before any source opens (owner, design 2); the engine's `runtime.New/Add/Activate/Run/Drain/Remove/Close` carry the lifecycle, the facade holding no goroutine.)* *(Annotated 2026-11-10, S3.3-2 ([design](../../sprints/s3-3-2-design.md) §9.1, known issue S3.3-1-2): once `Close` begins, `Deploy`, `Add` and `Activate` are refused with `ErrClosed`; `Close` waits, bounded by its ctx, for the calls already inside, then drains and removes every app; a `Remove` error that is not ctx's is part of its result.)*
   - Crash-consistency note: MVP has no snapshots; Stop is graceful-or-nothing, and the docs say so (roadmap honesty line).
4. **Ingest façade:** `AppHandle.Input(stream string) (cep.InputHandler, error)` — the programmatic feed (Siddhi's InputHandler analog); same path as sources (schema check, flags, Seq, registry, route). Used by the inmemory source, tests, and embedders.
5. **Tables — public API and write concurrency (review F15):** `AppHandle.Table(name) (cep.Table, error)` with `Upsert(fill func(cepio.RowWriter) error)`, `Delete(key any)`, `Load(fills []func(cepio.RowWriter) error)` *(annotated 2026-11-07, S3.3-1 (design §3.8): as built, `Upsert(ctx, fills ...)`, `Delete(ctx, keys ...func(cepio.RowWriter) error)` — a composite key cannot cross as `any`; the key fill sets primary-key columns only — and `Load(ctx, fills)`, a multi-row upsert; every call takes `ctx` because a write waits for the router (owner F14))* — the same RowWriter boundary (round-2 N3; cold path, conversion cost irrelevant) — the programmatic MVP path (SPEC §4.3). Internally a table is an immutable map behind an atomic pointer: writers (the table API, serialized through one lightweight mutex on the write path — writes are rare) build the next version and swap (`internal/table`'s `sync`/`sync/atomic` use is a named, fixture-enforced puritycheck exception (`archcheck`'s purity check, S1.1b) — ADR-0015 §2); readers (expr `in`-nodes on shards) load the pointer once per event evaluation — the lock-free snapshot-per-event SEMANTICS §4 requires, with zero reader coordination. `Walk` covers the current version (snapshot seam). *(Annotated 2026-11-04, owner decision at S3.1-2's design: the snapshot is not loaded by the `in`-nodes at evaluation; the runtime takes one per event at its ingest position and the expression reads it through `expr.Row.Table(id)` — SEMANTICS §4 as annotated; the carrier through the release buffer is S3.2a's.)* *(Annotated owner, 2026-11-05, S3.2a-2 F14 ([decisions](../../sprints/decisions.md#owner-decisions-2026-11-05--s32a-2s-design-after-the-architecture-review)): a live table write **enters the runtime's intake** and is applied by the router in intake order, so an event never reads a write made after it arrived, and a recording holds each write at its place. The write call returns once applied. The router is then the tables' only live writer.)*
6. Fault isolation at delivery (Siddhi's sync-mode fault propagation rejected): each consumer's delivery is independent; a panic inside one rule's processing is recovered at the shard boundary, converted to a per-rule event error (counted), and never skips other consumers' deliveries. *(Annotated owner, 2026-11-05, S3.2a-2 F10, F1 ([decisions](../../sprints/decisions.md#owner-decisions-2026-11-05--s32a-2s-design-after-the-architecture-review)): a rule body's panic is recovered in `partition`, per key. That key is **reset as a purge resets it** (state and timers go, its buffered events stay), the panic is counted, and the walk continues for every other key. A panic in partition's own code is the shard boundary's last resort: the shard calls `Advance` again until it returns. A sink's panic is recovered by its flusher and counted.)*

## Alternatives considered
- Depth-first synchronous junction (Siddhi sync mode) — rejected: couples latency of all consumers, breaks per-key isolation, fault-propagation hazard (study §10).
- Global stream namespace across apps — rejected: deployment isolation is the point of multi-app; cross-app coupling invites config-order bugs.
- Firing pending absences at Stop (wm→+∞ like playback end) — rejected for live Stop: a shutdown must not fabricate detections; playback end keeps +∞ semantics (a log END is evidence of absence; a process stop is not).

## Consequences
- Positive: fan-out/re-ingestion has one owner; multi-app is structural; shutdown is deterministic and sleep-free; the public lifecycle API is five methods.
- Negative: AppID threading touches every internal id — cheap now (F13 caught it pre-code), costly later; done now.

## Implementation notes for coding agents
- Routing table entries are precompiled at Start: key `Expr` (ADR-0011) + shard hash fn *(as built: a key attribute index, §1's annotation)*; the router is the ONLY writer to shard mailboxes and sink queues (ADR-0006 §5).
- Drain barrier implementation: a `CtlDrain{appID, upTo}` control message per shard; shards ack via the outbox; Stop waits on acks with ctx deadline.
- *(Annotated 2026-11-02: Go has no generic methods, so `InputHandler` ships `SendRow` only in sprint S3.3; the typed entry point — a generic function such as `cep.InputFor[T]` over the builder's struct mapping, with a named mapping owner — is designed in sprint S6.1.)* `cep.InputHandler.Send(ev T) error` (generics over the builder's struct mapping) and `SendRow(fill func(cepio.RowWriter) error) error` (the same public value boundary as sources — round-2 N3; internal/event.Value never crosses the facade); both return backpressure errors rather than blocking past ctx. *(Annotated 2026-11-07, S3.3-1 (design §3.1): as built, `SendRow(ctx, batchID string, fill)` and `EndBatch(ctx, batchID)` — `ctx` and the batch id for the batch-close signal.)*

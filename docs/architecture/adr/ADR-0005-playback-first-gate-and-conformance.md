# ADR-0005: Playback mode and the gate are built before any operator; the conformance suite is the operators' spec

## Status
Accepted (owner, 2026-11-01 — ratified with the enforcement conditions implemented in ADR-0015 and docs/development/qa-strategy.md).

## Context
Ground rule 13: the gate comes before the first feature. O1: deterministic replay built before the operators it tests. testing.md defines the four rules and the layers; DEVELOPMENT.md defines the gate registry and tiers T0–T4. The spec corpus (`docs/language/examples/` with `expect` blocks) and the semantics harness (`docs/language/checks/`, 40 checks) already exist as executable truth; Phase 1's engine must be graded against them from its first operator.

## Decision
1. **Stage 1 (sprints S1–S3, per the pre-mortem's capacity finding — one "sprint" was impossible) builds, in order and before any pattern/window operator exists:** S1 the gate + module + `event`/`model` kernels; S2 the parser + validator + grammar-differential; S3 the clock service + minimal runtime + playback + conformance runner proven over plain filter rules. `clock.Instance`'s and `StreamRegistry`'s signatures FREEZE at S3's exit gate — operator sprints build against a frozen contract. *(Annotated 2026-11-02 at the approved Phase-1 decomposition: sized honestly, the stages are split before entry — as recalibrated to the 13-point cap (v3): S1 = S1.1a + S1.1b + S1.2, S2 = S2.1 + S2.2a + S2.2b, S3 = S3.1 + S3.2a + S3.2b + S3.3 — so "S3's exit gate" is S3.3's G5; the playback drive loop is the runtime itself with one shard (S3.2b), and the expect sandbox lives in `internal/playback` (S3.3). The stage order is unchanged.)*
2. The gate implements DEVELOPMENT.md literally: `tools.json` manifest (pinned versions + checksums), one installer, a check registry (`gate/registry.json` — **the row schema is stated once, in ADR-0015 §1.1**, which is the gate's single normative mechanism catalog), `make check|combine-check|strict-gate` and CI (GitHub Actions) running the same rows; collect-all; zero-is-failure; the `job | step | verdict | time | reason` table (LAW Δ block first — ADR-0015 §1.3); `exit:` line. Linter choice (golangci-lint pinned) and hook wiring settled at S1's plan check.
3. **Playback** (`internal/playback`): input = a merged event log (JSON Lines; one object per event: stream, ts, attrs, optional batch id; plus optional explicit punctuation records; **plus table records** `{"table":"<Name>","op":"put"|"delete","row":{…}}` — SPEC v0.1 rev 2 / pre-mortem RC4: a table record is applied at its file position and its effect is visible to the next and every later event (SEMANTICS §4's snapshot-per-event rule); table records are part of the log, so a table-mutating session replays byte-identically — consistency review B2), replayed single-threaded through the real runtime with the virtual clock; output = the emitted events in order, canonically encoded. Byte-identical across runs and across machines on one engine build (SEMANTICS §10). **Byte-determinism pins (pre-mortem RC-5):** `cmd/*` binaries `import _ "time/tzdata"` and `cep.BuildInfo()` reports the tzdata, Go, x/text and engine versions; ingest decoding is schema-driven (never `encoding/json` into `map[string]any` — int64 beyond 2^53 must survive; ADR-0008); canonical encoding pins float formatting (`strconv.FormatFloat(f,'g',-1,64)`), timestamps as RFC3339 UTC millis, and defines NaN/±Inf as expression errors (never encodable); the T4 gate runs the playback suite on two OSes (linux, darwin) and byte-diffs the outputs. *(Annotated 2026-11-06, S3.2b-1's design v2 ([s3-2b-1-design.md](../../sprints/s3-2b-1-design.md) §4): "through the real runtime" is `runtime.Sync` — one app on one shard, each step run on the caller's goroutine through the live router's and shard's own steps; the playback driver owns a `Sync`, so a replay has exactly one ingest step. The second OS is macOS (owner, S3.2b's plan check Q5).)*
4. **The conformance runner** (`conformance/`): executes every `expect` block in `docs/language/examples/` through playback. **E-EXP-001 placement (review F7):** expect execution is a deploy-pipeline stage — `Deploy` runs parse → validate → plan → *execute expect blocks in an ephemeral playback sandbox* → activate; an expect failure aborts the deploy with E-EXP-001, which is how a [static] code can require running the rule. The runner and the deploy stage are one implementation. It executes every expect block in a **fresh sandbox per block** (SPEC §6.8 rev 2 — consistency review B2): tables start empty each block; `given table <Name> [rows]` sections are translated to table-load records prepended to the block's log **before** the first event, through the same internal table-load path `AppHandle.Table(...).Load` uses (the sandbox never runs `Start`, so seeding rides the log, not the public API — ADR-0012 §3); then multi-given sections, empty-then = assert nothing fired, omitted attrs unasserted — SPEC §6.8. Plus golden cases ported from `docs/language/checks/test_semantics.py` (each Go case cites its Python source check by name). The **grammar-differential is its own T4 registry row** (ADR-0002 §5), not part of this T2 run (consistency review S2). 100% pass from the first operator on; a case for a construct that does not exist yet is `skip: not-implemented(S<n>)` — recorded, never green, and failing T4 once its sprint closes (ADR-0015 §2 `todocheck`).
5. The expect-runner is also the **rule unit-test framework**'s core (O6): `cep validate` and `cep test <dir>` are thin drivers of the PUBLIC Deploy pipeline (parse→validate→plan→expect-sandbox) with activation suppressed — one implementation; the CLI never imports internals (ADR-0001 §2, round-2 F9).

## Alternatives considered
- **Operators first, harness after** — rejected by decided method (tests are the spec); the L2 experience (a "validated" harness contradicted by the spec) shows why the oracle must precede the implementation.
- **Separate test-only engine for playback** — rejected: playback must exercise the real runtime or it proves nothing; only the clock driver differs.

## Consequences
- Positive: every subsequent sprint lands with its conformance cases as entry criteria; agent waves get an objective gate; the demo's latency measurement (exit criterion 2) reuses playback instrumentation.
- Negative: S1 ships almost nothing user-visible — accepted deliberately (correct order over an early demo, sprint model §1).

## Implementation notes for coding agents
- Log format (`internal/playback/format.go`): `{"stream":"AgentActions","ts":"2026-01-01T10:00:00Z","attrs":{...},"batch":"b1"}`; table records: `{"table":"SensitiveResources","op":"put","row":{"resource":"vault"}}` (op `put` upserts by the table's key, `delete` removes; no ts — position in the file IS the ordering); timestamps RFC3339 in files, converted to int64 ms at load; file order = arrival order; the loader derives per-stream Seq. *(Annotated owner, 2026-11-05, S3.2a-1 D2, D3, D4, D6 ([decisions](../../sprints/decisions.md#owner-decisions-2026-11-05--s32a-1s-design-after-the-architecture-review); design [s3-2a-1-design.md](../../sprints/s3-2a-1-design.md) §5): an event line carries `ts` only when its stream has no time attribute; an event-time stream's time is its attribute. A **recording** starts with `{"recording":{"start":…}}`, gives each event-time event an `arrival` stamp, and carries `{"tick":…}` and a final `{"stop":true}` — replayed as live ingest applies them, in place of the virtual clock and +∞; a log without a header is a **fixture** (virtual clock, +∞ at the end). Replay streams and stops at the first fault (envelope, field, table record or payload); steps already delivered stand. Object values are stored compact with malformed UTF-8 as U+FFFD. The driver stamps Seq for every decoded event, stream-late ones included.)*
- Canonical output encoding = `model`'s canonical JSON rules (ADR-0003) applied to emitted events: sorted keys, explicit nulls, RFC3339 UTC.
- The ported harness cases live in `conformance/semantics_test.go`; the Python harness is NOT deleted — the gate's T4 runs both until Phase 2 retires the Python side by owner decision.

## 2. Lane E1 — the scan (python-engineer, W1)

**2.1 The loader** (`gate/runner/rows/gomods.py`, replacing the stub; lifted from `rows/deps.py:43-92`):
- `load(row_dir, env) -> Loaded` runs, in each of `MODULES` (`.`, `gate/proofs`), with the row's `ENV` (`rows/deps.py:27`): `go list -m -json all` (the build list, the main module skipped; `Replace` read as today, `:66-72`); `go mod graph` (`deps.graph_nodes`); then **for each of `PLATFORMS`** with `GOOS`/`GOARCH` set: `go list -e -json -deps -test ./...`, and in `gate/proofs` also `go list -e -json -deps tool` (the `tool` pattern — review A-L7; it replaces `TOOL`, `rows/deps.py:25`). Every `go` call goes through one `run(...)` that keeps stdout and stderr in `row_dir` (`rows/deps.py:36-42`) and raises `Failed` on a non-zero exit.
- The `-json` stream is decoded object by object (`json.JSONDecoder.raw_decode` over the concatenated objects). For each package: `Standard: true` → skipped; else `Module.Path` empty → error `gomods: <ImportPath> (<module dir>, <goos>/<goarch>): no module`; `Error.Err` non-empty → `gomods: <ImportPath> (<module dir>, <goos>/<goarch>): <Err's first line>`; each `DepsErrors[].Err` → the same form; otherwise `Module.Path` (or `Module.Replace.Path` never — the compiled set is keyed by the required path) joins the compiled set. **Measured at E1's first commit:** which packages `-test` adds with no `Module` (the generated `<pkg>.test` mains) — those are named in a pinned skip list by their `ImportPath` suffix `.test`, never by a blanket rule; the skip list's size is pinned.
- `Module(path, version, replace, built)`: `version` the build list's; `replace` `"<path> <version>"`, `"<path>"` for a directory, `""`; `built` true when the compiled set holds `path` on either platform. A module selected by both build lists appears once (the root's version first, as `rows/deps.py:91`; the `deps` row's one-version check is unchanged) and is built if either side builds it (review QA-L5).
- `Loaded.errors` is sorted; `rows/deps.py` and `rows/vulns.py` each print every error line as a fault (review A-B1). `deps.Module.imported` reads `gomods.Module.built`.

**2.2 The matcher** (`gate/runner/vulndb.py`):
- **Versions.** `_parse(text) -> tuple` accepts `MAJOR.MINOR.PATCH` with an optional `-PRERELEASE` and an optional `+BUILD` (dropped — `+incompatible` included, on both sides; review QA-S4); a leading `v` is stripped first; anything else raises `InvalidVersion(text)`. Order: the core numerically; a version with a pre-release before the same core without; pre-release identifiers split on `.`, numeric identifiers numerically and before alphanumeric ones, then by length — semver 2.0, which is x/mod's `semver.Compare` (the agreement table proves it). A pseudo-version `0.0.0-20261106192419-47ce03d25ef0` is a pre-release of `0.0.0` and sorts below it.
- **`go_version`.** `go1.27.4` → `1.27.4`; `go1.27` → `1.27.0`; `go1.28rc1` → `1.28.0-rc.1`; `go1.28beta2` → `1.28.0-beta.2`; anything else (`devel …`, `go1.27.4 X:…`) → `InvalidVersion` (x/vuln's `GoTagToSemver`, mirrored, and tabled).
- **`affected(version, ranges)`** (x/vuln v1.9.0 `internal/semver/affects.go:13-90`, the plan check §0.17): no ranges → `True`; no range of type `SEMVER` → `True`; for each SEMVER range: events sorted with `introduced "0"` first and the rest by their version; walking them, `introduced` opens (`"0"` always; else `version >= introduced`), `fixed` closes (`version < fixed`); any event key other than `introduced` and `fixed` → `InvalidVersion`-like `UnknownEvent(key)` (a named red; `last_affected` and `limit` are unused by the Go database today, §0.1). True if any range holds the version.
- **`findings(modules, never_built, go_version, entries)`**: for each entry not `withdrawn`, each `affected` block whose `package.ecosystem` is `Go` and whose `package.name` is a key of `modules`, `stdlib` or `toolchain` (both at `go_version`): if `affected(...)`, a `Finding(id, module, version, fixed, built=module not in never_built)` where `fixed` is the smallest `fixed` event greater than `version` in the range that holds it, `""` when none. Two blocks naming one module give one finding per entry and module (35 entries have two blocks today — review QA-S4). Sorted by `(module, id)`.
- **Faults raised to the row** as exceptions carrying the entry id: `vulns: <id>: unknown range event <key>`; `vulns: <id> <module>: version <v> cannot be ordered` (either side; review QA-S4).

**2.3 The copy and the fetch** (`gate/toolchain/vulndb_fetch.py`, the network edge, beside the installer — review A-L2):
- `copy_root(environ) -> str`: `VORSAR_CEP_VULNDB` if set (absolute), else `$HOME/.cache/vorsar/cep/vulndb` — `manifest.cache_root`'s shape (`manifest.py:76-82`). `VORSAR_CEP_VULNDB` joins `support.HIDDEN` (`gate/proofs/drivers/support.py:36`; review QA-S2).
- `main(argv, environ) -> int` (run by `make vulndb` → `python3 -I -B gate/bootstrap.py exec -- fetch-vulndb`, dispatched in `gate/runner/main.py` beside `generate-ci`, `:170`): one GET of `CANONICAL_URL` with the installer's timeout (`install.DOWNLOAD_TIMEOUT_S`, read through `install._fetch`'s pattern), into a temp file in `copy_root`, stopping past **`FETCH_CAP` = 64 MiB** (about 21× today's 2.97 MB); then `vulndb.zip` and `stamp.json` (`{"fetched": "<UTC, YYYY-MM-DDTHH:MM:SSZ>", "sha256": "<zip>", "url": CANONICAL_URL}`) each written by temp file and `os.replace`, zip first; `fetch-error.txt` removed. On any failure: `fetch-error.txt` written (`<UTC time> <first line of the error>`), the old copy left as it was, `vulndb: <error>` printed, exit 2. Exit 0 on success, printing `vulndb: fetched <bytes> bytes, sha256 <12 hex>, modified <db.json's modified>`.
- In CI the step is `make vulndb` with `continue-on-error: true` (review A-S3, QA-S8): a failed fetch never skips the runner; the row names it.

**2.4 `check_db(read, stamp, *, zip_sha256, now)`** — each fault one line, all collected (never the first only):
- `stamp` None → `vulns: no stamp.json at <root>: run make vulndb`; not an object with exactly `fetched`, `sha256`, `url` (strings) → `vulns: stamp.json is malformed: <why>`; `sha256 != zip_sha256` → `vulns: the zip's sha256 is not the stamp's: run make vulndb`; `url != CANONICAL_URL` → `vulns: the copy came from <url>, not <canonical>`; `fetched` unparsable → malformed; `fetched > now` → `vulns: the copy's fetched time <f> is in the future`; `(now.date() − fetched.date()).days > 7` (UTC calendar days — review QA-S7) → `vulns: the copy was fetched <d> days ago (<day>), more than 7: run make vulndb`.
- `index/db.json` missing or not `{"modified": <RFC 3339>}` → `vulns: index/db.json is missing or malformed`; `modified > fetched` → `vulns: the database's modified <m> is after the copy's fetched <f>`; `modified > now` → in the future; `(now.date() − modified.date()).days > 30` → `vulns: the database has not changed since <day> (<d> days, more than 30): check vuln.go.dev, or add a dated vulndb exemption naming a known issue`.
- `index/modules.json` not a non-empty list of `{path, vulns}` → `vulns: index/modules.json is missing, malformed or empty`; `index/vulns.json` likewise; an id in `vulns.json` with no `ID/<id>.json` → `vulns: <id> is listed in index/vulns.json but ID/<id>.json is missing`; a `(module, id)` pair in `modules.json` that the entry's `affected` does not name, or the reverse → `vulns: index/modules.json and ID/<id>.json disagree on <module>` (review QA-L2; zero today).
- Members whose names begin with a directory other than `index/` and `ID/` → `vulns: member <name> is outside index/ and ID/: not the database's layout` (review A-L5); a member whose decompressed bytes pass **`MEMBER_CAP` = 4 MiB** (about 7× the largest today) → `vulns: member <name> exceeds 4 MiB`. The row's `read` counts decompressed bytes as it reads (`ZipFile.open` and a bounded `read(MEMBER_CAP + 1)`), never trusting the header's size.

An empty module set → `vulns: no module read`.

A `<id> <module>` entry silences that one finding only (review QA-S5); one that matches no finding this run → `vulns: <target> matches no finding: remove it`; a malformed target → `vulns: <target>: not "<id> <module>" or "vulndb"`. **The `vulndb` entry** (decision 2) silences every copy and database fault of 2.4 and the failed-fetch fault — never a finding; with it in force and no usable copy the row passes with `not scanned: <the first silenced fault>; exempted by vulndb until <expiry> (<issue>)` (it reads the module files, so covered stays 6).
- **Faults:** each red finding `vulns: <id> <module> <version>: fixed in <fixed>` (`no fix yet` when empty); the loader's errors; 2.4's faults; the waivers' faults.
- **Reason** (green): `vulndb <modified day> (fetched <day>, <root>), <n> entries; <m> modules (<b> built); stdlib and toolchain at <go>; never built: <id> <module> <version> fixed <v>, …` (the never-built findings by name, each — decision 1); and, by decision 5, `not read: golangci-lint (Go build info, from S1.1c-5); ruff, CPython (outside the Go database)`.

## 4. Lanes F1 and F2 — the canary (python-engineer, W1–W3)

**4.1 `install.archive_pins(archive, strip, executables)`** (F1; review A-L1): `_install_tool` (`install.py:251-288`) is split so its extract-and-seal steps are one private helper, `_extract_sealed(archive, strip, dest) -> dict[str, int]` (the modes), used by both; `archive_pins` extracts into a temp dir, seals, returns `ArchivePins(manifest.tree_sha256(tmp), {rel: manifest.sha256_file(tmp/rel) for rel in executables})`, then `_restore_write` and removes it. The installer's stamp file is written after the helper and outside the hashed tree, as today (F1 confirms by reproducing a committed pin). Equivalence test over a small synthetic `.tar.gz` (an executable, a symlink, a nested directory): the installer's published tree and `archive_pins` give the same tree hash. The one-off reproduction of R-V2 §6's ruff 0.17.3 pins goes in F1's report, not in a test.

**4.2 The feeds** (`gate/canary/feeds.py`, the network edge, thin): `fetch(pinned, *, token, get) -> dict[str, object]`, one request per tool — go `https://go.dev/dl/?mode=json`; golangci-lint, ruff `https://api.github.com/repos/<owner>/<repo>/releases?per_page=30`; python and python-floor (one feed) `…/astral-sh/python-build-standalone/releases?per_page=10`; lark `https://pypi.org/pypi/lark/json`. `Authorization: Bearer <token>` on GitHub requests only. A non-200 → `CanaryError("<tool>: <url> answered <status>")`; a 403 or 429 with `x-ratelimit-remaining: 0` → `CanaryError("<tool>: GitHub's rate limit (<limit>/h) is spent until <reset UTC>")`.

**4.3 `candidate.build(pinned, feeds, archive)`** (F1): per tool, the latest release that is **stable** (not `prerelease`, not `draft`; go's `stable: true`; PyPI's non-yanked) **on the pin's own line** — go `1.27.*`; golangci-lint `v2.15.*`; ruff `0.17.*`; python `3.15.*` and python-floor `3.12.*` within the newest python-build-standalone tag that ships them; lark `1.3.*` — never older than the pin (`CanaryError("<tool>: the newest on its line, <v>, is older than the pin <p>")`). A newer line is listed, never tried (`Candidate.newer_lines`: e.g. `golangci-lint v2.16.0`) — the owner's G1 question (§7). Per platform the asset by the pin's naming pattern; its digest from the feed (GitHub `digest` `sha256:…`, go `sha256`, PyPI `digests.sha256`) — missing → `CanaryError("<tool> <platform>: no published digest")`; `archive(url, sha256)` downloads and checks it (`CanaryError("<tool> <platform>: the download's sha256 is not the published one")`); `archive_pins` gives the hashes; `version_line` is filled by the workflow's Linux job running `version_argv` from the Linux tree (go's template keeps `{goos}/{goarch}`). A CPython patch move (`3.15.2` → `3.15.3`) is an upgrade named as such. The result passes `manifest.load` for both platforms.

**4.4 `candidate.structural_faults(pinned, candidate, upgraded)`** (review QA-S9): every key path where the two documents differ, other than `version`, `version_line`, and each platform's `url`, `archive_sha256`, `exec_sha256` values (not keys) and `tree_sha256`, for a tool in `upgraded` → `canary: <tool>.<key path> changed: <a> → <b>`; a tool added, removed or moved → named.

**4.5 The sort** (`gate/canary/sort.py`): `sort(records, pin_tests, structural) -> Sorted(pins, breaks)`: a red record whose row and failing test id are in `PIN_TESTS` and whose failure text matches that test's pattern goes to `pins` **only when `structural` is `[]`**; everything else to `breaks`. `PIN_TESTS` — the exact test ids and failure-text patterns, and the non-test reds (the `go.mod` toolchain lines, `census.md`, the LAW Δ block) — is **measured in F1's first commit** from one local T4 run under a ruff 0.17.5 candidate (`tools.json` swapped in a scratch worktree), the run's reds quoted in F1's report. How a Python test row exposes a failing test's id and text (its per-module report files, `rows/__init__.py:75-77`) is read in the same run.

**4.6 The summary** (`gate/canary/summary.py`): Markdown; the first line always `Upgrades: <tool> <pin> → <latest>, …` or `Upgrades: none`; then `New lines (not tried): …`; then `Pins to update: <test id> (<file>), …`; then `Breaks: <row>: <reason>, …`; for a ruff or golangci-lint upgrade, `Suppression tables not re-measured (test_suppressions.py holds them as data)` (review QA-S10). Exit 0 with no breaks, 1 with any (the canary is a report — confirm (f)).

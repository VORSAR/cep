**How I applied severity.** I used the brief's definitions. Blocker: a rule whose only planned proof cannot fail, cannot pass for the right reason, or has a wrong expected value; an exit line that cannot be proven; or a false-green path. A rule with no test whose failure is a hang, a confusing message or a loud red (never a wrong green) is should-fix, and I say so in its row.

## P1: what QA's red tables must assert under each option

**Option (a), keep §4.**
- Assert the `Type` values (`TString == 0` … `TObject == 6`) and the underlying type `uint8` (via `reflect` in the test).

## What I checked and found sound

- The `exec_sha256` Go list (go, gofmt, compile, link, vet, cover, asm) matches what go1.27.3 actually runs for build, vet and `test -cover` (probe `m3/`: asm, compile, cover, link, vet).
- The parity hashing cost is plausible: SHA-256 runs at 0.051 s per 150 MiB in memory (about 2.9 GiB/s), and the Go executables total about 69 MB.
- `unit`'s count (distinct packages with a package-level pass or fail) equals `go list`'s count, external test packages included (probe: 5 = 5).
- The summary example's footer arithmetic is right: summed 42.7 s; (42700 − 31000) × 100 // 42700 = 27.
- `test_coverage_below`'s "88.88%" is consistent with S6's truncation rule (C29); exact-text assertions stop the coverage drivers passing on a build failure.
- The FIFO open order (write-then-read against read-then-write) cannot deadlock with two workers; with one worker, both rows time out, so that case needs no witness.
- A trace written only by the scheduler, with its own sequence numbers, is a sound witness basis for C2 and C3.
- Parity as the one hard stop, with "the trace has only parity", is a good assertion once the registry under test holds other rows (assert their "not run" records).
- `Compare` as a `cmp.Compare` chain, with exact −1/0/+1 assertions (PCv1 cases 31–37, C36, C37), catches subtraction and field-order mutants.
- On darwin, a group check right after the leader exits showed no false "still running" from an already exited grandchild (0/200; Linux not probed, DQ34).
- `os.rename` refusing an existing final directory (C24) is the right primitive.
- Under (b), the zero `Kind` and the `String()` table give tables that start red against the stub.
- Sorting before output, and pinned JSON options, address hash-order nondeterminism in output, provided the seed problem in DQ18 is fixed so that it can actually be tested.

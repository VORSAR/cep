## Findings

**RA-1 — blocker. A net reads "caught" even when its test also fails without the plant.** `gate/bench/mutate.py:1054-1066` (`batch`) counts red outcomes and never runs the designated test unplanted; its docstring (`:61-71`) says "Only red counts"; the plan's judge (§2 S1, §6 1–11) has no unplanted control either. The nets job's setup differs from the test job's (module download, vulndb and history keyed by row id: `gate/ci/generate.py:64,68,78,225-227`); 132 of the 296 nets are Python gate tests, 11 in `gate.toolchain.tests`. A test that fails at HEAD for any reason marks every net on it caught, and exit 3 passes while guarding nothing — a missed detection. **Fix:** run each distinct (pkg, test) or py id once unplanted, in the same worktree and environment, before its nets; not green → its nets red "invalid: fails without its plant"; counter-example (12); budget about 103 distinct Go tests in N4.

**RA-2 — should-fix (high). Stale nets show only at the nightly, so normal PRs will stop the line.** The nets row is nightly-only; nets sit in busy files (`gate/bench/mutate.py` 67, `internal/runtime/recorder.go` 23, `drain.go` 20, `partition.go` 11, `table.go` 11); Q2(a)'s "fixes it in the same commit" has no PR-time enforcement. A PR editing a line under a net's find text merges green and the next nightly is red (ground rule 11), after every such PR, S4.1's included. **Fix:** a static anchors check at T2 with the same loader (find exactly once, hunks apply, file tracked, test listed, py importable), seconds and no builds; the nightly then judges only caught or escaped; ask the owner, since it adds a PR row (Q4).

**RA-3 — should-fix. Splitting mutate.py into a library makes 67 nets stale and reverses a dependency direction.** 67 of 296 nets plant into `gate/bench/mutate.py` and 72 test `gate.bench.tests`. Cypher on IMPORTS shows only bench→runner edges (mutate→jsonstream/rows/stress, load→stress, escapes→env); nothing in `gate/runner` imports `gate/bench` (`gate/runner/testnames.py:145` copies an algorithm to avoid it); `impact(run_one)` is HIGH (4 processes). **Fix:** don't split; put the row module in `gate/bench/nets.py` (rows already live outside `rows/`: `gate/coverage/main.py`, `gate/proofs/row.py`); import `entry`, `changes_of`, `Worktrees`, `run_one`; the one change to mutate.py is typed refusals (`class Stale(Refused)`).

**RA-4 — should-fix. The seed set and §2's schema don't match the plants.** Five of the 296 expect green at the new revision (robustness plants G2-47, G2-15, G2-97, g2-117, G2-151-live) and read "escaped" under a caught/escaped judge. 44 entries carry `subtest`; 11 use per-revision targets. starve-5 names `TestFullQueueWithABusyRecorderGetsNoTurn`, which exists only in the design doc. **Fix:** `subtest` in the schema; map `new_*` keys; the five green plants `"expect": "green"` or retired with a reason; annotate §0 item 2.

**RA-5 — should-fix. Q3's options are mis-costed and a cheaper one is missing.** The test rows are T2–T4, so `--tier nightly --job test` selects zero rows and `registry.select` refuses it (`gate/runner/registry.py:234-242`); the summary's expected set is the registry's (job, id) and any other record is FAIL "unknown row" (`gate/runner/summarize.py:176-213`). Option (a′): add `nightly` to the chosen rows' tiers and key `RUNNERS` by (tier, job), so the nightly `test` job runs on `macos-latest`; records stay (test, unit); no summary change, no new instruments or drivers; cost: the instruments' `tiers` in law (`teeth.py:484,521-524`), a few generator lines and a `test_generate` case; mixed tiers already exist (vulns). Option (b): six instruments plus six drivers. "Six rows" is the T2 set; at T4 the test job has nine.

**RA-6 — should-fix. Proof (17) and exit 5 can't be a proof driver.** Drivers run in the T4 proofs row on ubuntu; the nightly runs none; `determinism-macos`'s driver runs its row on Linux (`gate/proofs/drivers/test_determinism_macos_planted.py:24-38`). **Fix:** a `test_generate` case (nightly test job on macOS, T4 on ubuntu); the summary's rule that a missing job's rows read red; one dispatched nightly on a scratch branch with a `runtime.GOOS == "darwin"` plant, recorded and never committed.

**RA-7 — should-fix. "Nothing in this sprint adds to PR CI" is false.** Every new row's planted proof runs in the T4 proofs row (exclusive, 600 s, 227–362 s today); drivers run in parallel, one per CPU (`gate/runner/rows/__init__.py:130-146`); `stress.hog_count()` is 2 × CPUs (`gate/runner/stress.py:60-61`). New drivers: four race packages, cpu, load, stress, nets (escaped and stale), the timing list. Load and stress drivers starting hogs beside about 40 parallel drivers slow the row and make timing-sensitive drivers flaky. **Fix:** a time budget per driver; `--hogs 0` / `--no-hogs` in their worlds; the proofs row's time before and after; exit 7 measured on the proofs job.

**RA-8 — should-fix. The S3 job split breaks three drivers lane C doesn't own.** `test_fuzz_parser_planted.py:40-45`, `test_fuzz_decoder_planted.py:40-45` and `test_racestress_planted.py:25-29` assert job `"nightly"`; `support.registry_row` copies the real row, job included (`gate/proofs/drivers/support.py:89-96`). **Fix:** C owns all three; the coordinator's registry edit lands in the same commit as the driver edits.

**RA-9 — should-fix. Dispatched nightlies can be cancelled.** The concurrency group is `nightly` for every ref with cancel-in-progress false (`gate/ci/generate.py:205-206`, `.github/workflows/nightly.yml:9-11`); GitHub keeps one running and one pending run per group and cancels the older pending one (from GitHub's documentation as recalled, not tested). **Fix:** lane M sets the group to `nightly-${{ github.ref }}` with a `test_generate` case.

**RA-10 — should-fix. `--changed` is under-specified and unsound as a rename PR's proof.** A net has no field naming its test's file; `--changed` selects nothing when a diff changes a helper a test calls (`q2Start`, `internal/playback/helpers_s3_2b_2_test.go:92`, 22 tests), when S1.1c-13 moves a test, or when only `gate/nets.json` changes; the full set is 7–10 minutes. **Fix:** rename PRs run the whole nets row; drop `--changed`, or make it a strict superset and never the proof of record.

**RA-11 — should-fix. A watchdog kill loses the per-net verdicts.** Per-entry timeouts (17 at 300 s, 18 at 180 s, about 250 at the default) sum far above `TIMEOUT_MAX_S` = 3600 (`gate/runner/registry.py:19`); the scheduler sends SIGTERM then SIGKILL (`gate/runner/scheduler.py:485-498`). **Fix:** stop starting entries when the remaining budget cannot hold the next timeout, naming the rest "not run"; write each verdict as it comes; clean worktrees on SIGTERM via `term.install()`.

**RA-12 — should-fix. Q2 quietly changes a recorded decision.** 2026-11-22 A says "a nightly row re-runs the committed plant batches against HEAD"; the plan runs a curated copy. Better, but under ground rule 4 the question must say so; Q2 should also list a per-entry runner over the batches in place.

**RA-13 — should-fix. Wave 2 has a file-ownership collision.** Nobody owns `gate/runner/stress.py` or `gate/bench/load.py`, yet lane A works on mutate.py (which imports stress.py) while lane L builds on both; the nets instrument's `code` list is its import closure (`gate/runner/tests/test_instruments_pin.py:218-295`). **Fix:** L owns both files, A must not change them, the coordinator applies closure-driven law edits at the wave's end.

**RA-14 — later. The rename measure is incomplete.** By file path against the survey index: 268 of 296 nets plant into or test from a file with a G3–G6 or G8 finding (G5 248, G4 106, G8 82, G6 43, G3 30); the plan should report G4 and G8.

**RA-15 — later. Imprecise statements.** The nightly has two jobs plus strict-gate (a 17-minute `lint` job too); `workers.py:16-19` is the worker-count parser, the concurrency is in `scheduler.py`; §0 item 3's 222 (225 find-once with `test`/`py`, 10 with only per-revision targets); unit's 600 s is the row's watchdog while go's 10 m is per package; R1: `gh repo view` reports PUBLIC, so minutes are free and the binding limits are concurrency (20 jobs, 5 macOS — inferred) and the 6-hour job cap.

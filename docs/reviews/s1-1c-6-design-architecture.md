### Should-fix

**DA-S1 — The mutation runner would count a mutant that does not build, or fails `go vet` inside `go test`, as red; and it writes into tracked files when a crash-safe alternative exists.** §3.2's red is "the command failed"; many named mutations remove a `return err` after `err :=` ("declared and not used"), and `go test` runs vet first — both a false "shown red". The wall-clock limit must kill the process group (`go test` starts the test binary as a child; precedent `gate/runner/tests/test_breakit_leak.py`). `go test -overlay=<json>` builds the mutant and leaves the file byte-identical (proved in a scratch module: plain run exit 0; overlay run `--- FAIL ... mutant killed` exit 1; file unchanged) — no restore step, no SIGKILL window, no risk of staging a mutated file. **Fix** (§3.2): red only when the build succeeded and at least one named test reported `--- FAIL` (or panicked); a build or vet failure is exit 2, "invalid mutant"; use `-overlay`; `start_new_session` and kill the group on timeout; force `-count=1`; tests for each.

**DA-S2 — The comparer's statistics are under-specified where it matters.** Go prints ns/op ≥ 999.95 as integers (`$GOROOT/src/testing/benchmark.go:644-645`); the runtime paths are 1334, 1901, 1179 ns; ten samples within 2–3 % will often tie, so the p-value must be the exact *conditional* permutation distribution of the observed midranks (dynamic programming over doubled midranks, or enumerating C(20,10) = 184,756 splits). "Before first" in every pair builds in a drift bias; alternate ABBA. A regex matching no benchmark gives exit 0 (testing rule 4: a run that selects zero tests fails). "Re-run once" does not say which run decides. B/op equality compares integer-truncated averages over runs whose b.N differs (inferred fragile). **Fix** (§3.1): the exact conditional p, tested against brute-force enumeration with ties; ABBA order; zero matched benchmarks exit 2; "costs" only if both runs say so, both quoted; allocations in a separate fixed-iteration pass (`-test.benchtime=<N>x`); an A/A self-comparison in the tests and once per session by the coordinator.

**DA-S3 — The commit plans bundle several hot functions per commit, defeating decision 1's per-function verdict and the "replaced in its own slot" fallback; the stated baseline mis-attributes cost.** Bundles: R9 (`route`, `routeKey`, `broadcast`), R10 (`Send`, `SendPayload`), R13 (three files), E5 (five scanner functions plus `member`, `exponent` — §6 E.2.5 itself says decision 1 decides them per function), P4 (three encoders), P7 (four reader functions); §2.2(3) says one split commit per source file or concern. §2.4.3 builds binaries "at the nets commit and at the split commit", so R2's commit 8 (`process`) would include `ingest`'s and `take`'s costs. **Fix** (§2.2, §2.4.3, each commit table): one hot function, or one benchmark-attributable unit, per split commit; compare `c^` vs `c`; a lane-level path comparison (nets commit vs lane head) at each hand-back; about 8 more commits.

**DA-S4 — The PERMANENT waiver template would be red at T0 for most candidates.** `//nolint:gocyclo,funlen` (§2.4.4, §6 E.2.1): `funlen` fires only past 60 lines, and `appendUnescaped` is 50 (`internal/event/decode.go:424-473`), `number` 33 (`:750-782`), `eventRecord` 54 (`internal/playback/reader.go:463-516`); `nolintlint` `allow-unused = false` makes an unused `funlen` a finding. The waiver line with `reason=` and `ref=` passes 120 characters; the precedent is `//nolint:gocyclo,lll` with "the waiver cannot wrap" (`internal/table/table.go:240`). **Fix:** name exactly the size linters that fire on that function, plus `lll`.

**DA-S5 — `broadcast(m message)` scatters an invariant whose zero value is wrong.** Today `broadcast` sets `admStream: -1` once (`internal/runtime/runtime.go:1119`); three callers would each have to; a forgotten field is 0 (stream 0), and `process` applies the admission when `m.admStream >= 0 && m.adm != math.MinInt64` (`runtime.go:1425`) — `adm` is 0, so stream 0's on-arrival rules would silently take a 0 watermark (the note names this very mistake as a mutation). **Fix** (§4 item 6): `broadcast` assigns `m.admStream = -1` itself; callers set kind, app, adv, tables, token, final; a mutation on that assignment.

**DA-S6 — Playback's `recordKind(present func(int) bool)` turns about 20 inlined calls per replayed line into indirect calls; the note says "at most a few direct calls".** `-m=2`: "inlining call to (*Reader).record.func1" at `internal/playback/reader.go:281` (the kind loop, 7 kinds) and `:291` (the allowed-key loop, `eCount` = 13); a func-value parameter of a non-inlined function is called indirectly. **Fix** (§8 P.2 `record`): `recordKind` takes `vals []event.Value` and tests `!vals[i].Null`, or calls an inlinable top-level `present(vals, i)`; the closure stays for the per-kind functions.

**DA-S7 — `plan.(*body).OnEvent` has no time net.** §9 Q.3 measures it "under the Send path benchmark (lane R's net)", but that benchmark's body "emits nothing" and runtime tests build stub bodies (`rtBodies`, `internal/runtime/api_test.go:47-221`), so `OnEvent` is never reached; `internal/plan` and `internal/partition` have no benchmark; it is a lane-R file lane Q's branch may not have. **Fix** (§9 Q.3): `BenchmarkBodyOnEvent/{filtered-out, projected, widened}` in package `plan`, in lane Q's nets.

**DA-S8 — Some tests can exist only after the split, breaking the note's rule that no test file is edited after the nets commit.** `TestActivationRefusalByPhase` "after the split" (§4 §3); E-Q1's "direct helper case" on `rfc3339Fraction` (§6). Many named mutations target helpers absent at the nets commit (`inputApp`, `ack`, `isSpace`), while plan check §7 places mutations in the nets commit. **Fix** (§2.2, §2.3): drop the post-split tests or allow one named post-split test commit per lane, excluded from the diff check; state when each mutation runs (new tests at the nets commit; transfers on the split commit).

**DA-S9 — Q3 mixes guards that in-package tests reach with blocks no test can reach.** §4 Q-R2 says the `a == nil` slot guards are "reached by the in-place tests" (R1 adds a "/nil slot" case), yet §10 Q3 lists them under the new reason. Truly unreachable: `boundary.go:114-116`, `reader.go:99-110`, `:269`, `:524`. **Fix** (§10 Q2/Q3): two lists — (a) reached only by white-box state (decision 2 met; a note); (b) unreachable by any test (these alone need the owner's third reason).

**DA-S10 — Three different escape-diff normalisers, one on a wrong premise, none tooled.** §2.4.2: a multiset per package, names stripped; §6 E.3: "`-m=2` escape lines name no function, so the E.1 line ranges stand in" — wrong: `-m=2` prints headers like "rk.name escapes to heap in (*Reader).record:" (measured); §8 P.3: per function name. A package multiset misses an escape that moves from a cold path to a hot one with the same text (E2's `moved to heap: de` leaving its `if`); decision 1 asks "no new heap escape *in the function*". **Fix** (§2.4): one normaliser as a third W0 tool with tests — per original function, the multiset over that function plus its named helpers, using the "in F:" lines; package-level counts as a backstop; say that E2-type moves are caught by the pins, not the diff.

**DA-S11 — The sub-lane cut does not fit the time box.** Plan check §8.9: 30 minutes per sub-lane; the spike: concurrent lifecycle and loop functions 25–35 minutes each, 7 of them; ~7 agent-hours for runtime plus validate. R1 alone (nets for 12 functions, ~45 tests, stress runs) is multi-hour; sprint model §11: "a lane fits one usage window"; PA-S15 raised it. **Fix** (§1, §4 §6, §5 §6): re-cut R and V by the spike's rates (e.g. R1a router and boundary nets; R1b lifecycle nets) and state each sub-lane's box.

**DA-S12 — The measurement windows and the costed-split replacement are not scheduled.** "The coordinator measures alone" while two agents run; ~31 hot functions × 10 ABBA pairs × up to 8 sub-benchmarks, with re-runs: an hour or more of exclusive time (inferred). A "costs" verdict on E4 arrives after E5–E8 are built on it; replacing a commit mid-branch needs a scripted re-cherry-pick (`git rebase -i` unavailable). **Fix** (§1, §2.5): fixed measurement points at each hand-back with both slots idle; file-disjoint split commits; the replacement as a written, scripted rebuild of the lane branch.

## Pre-mortem — two weeks on, the sprint failed. Why?

1. **The measurement gate became the critical path:** tie-heavy integer ns/op through a tie-free p and a before-first drift gave spurious "costs" verdicts, each forcing a scripted rewrite; the sprint closed late with waivers on functions that should have split. *Early sign:* the first lane's comparisons take more than an hour, or an A/A run says "costs". *Mitigation:* DA-S2, DA-S3, DA-S12.
2. **The nets were weaker than recorded:** non-building mutants logged as red; the break-it found a regression in an unproven split (the `admStream` default, or a lifecycle transfer). *Early sign:* a red mutation whose output names no `--- FAIL`. *Mitigation:* DA-S1, DA-S5.
3. **The lanes did not fit their boxes:** R1's nets ran past the box and the usage window. *Mitigation:* DA-S11.
4. **The path cost added up unseen:** each split under 2 %, together ~3 % on SendPayload at the pre-T4 comparison, with no remedy budgeted. *Mitigation:* DA-S3's lane-level path check and the missing question.
5. **G1 came back on the merge** once the fence was raised, delaying slot B. *Mitigation:* DA-B1's re-framing.

**Inversion (what makes it succeed):** per-function commits with `c^`-vs-`c` binaries; a runner that cannot false-red and never touches the tree; quiet windows at hand-backs; sub-lanes sized by measured rates; the merge kept to validate↔plan.

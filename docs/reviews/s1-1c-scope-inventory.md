# S1.1c scope inventory — a reading of main @ 9cd4188 (2026-11-10), for the pre-plan-check panel

This is NOT the plan check. It is the coordinator's inventory of what the owner's decisions place in S1.1c, what
exists in the code today, and what each item's subject is today. The panel reviews this inventory: is it complete,
is each item still justified, what should be dropped/forwarded/split, and what does the sizing say.

## 1. The thesis under review (steelmanned)

S1.1c builds the gate extras the owner moved out of S1.1b and S1.2 on 2026-11-04 to reach engine code fast, plus
four items forwarded since. It runs now, after S3.3's clock freeze and before S4.1 (the pattern engine), because:
(a) from S4.1 on every sprint changes law files (rules.json, registry, SPEC, goldens, baselines) and the owner reads
those changes by hand today — nine sprint records already carry a "rule-file changes, by hand" list; (b) the
not-built corpus entries (conformance/corpus_test.go `notBuilt`) need an expiry before S4.1 arrives, or a construct
can ship with its corpus file still marked not-built; (c) the dependency allowlist exists as law but nothing
checks go.mod against it; (d) with the engine about to grow fast, the lint/TODO/suppression nets are cheapest to
land while the code is small (archcheck's retroactive scan precedent).

## Findings

**RQ-1 — blocker. Five of the "296 re-runnable" plants are not nets: their record says the test must pass with the plant.** Five non-control entries carry `expect.new: "green"`: `A1-3-G2-47.json#0` (G2-47, ruff.toml), `A2-C7.json#0` (G2-15, `gate/current-sprint`), `W0-go.json#4` (G2-151-live, purity.json), `B-K2b.json#2` (G2-97, a 25 ms sink slowdown), `E1-C2.json#4` (g2-117, a 400 ms drain sleep) — tolerance proofs. Three of them plus starve-3, run at HEAD as one batch: `counts: red 1, green 3, timeout 0, invalid 0` (9.4 s). starve-3 is recorded "may be red only some of the time"; the G10-20 race plants were caught 3 of 50 under `--race --repeat 50 --load` (`docs/sprints/s1-1c-7-record.md:382`). §2's schema has no polarity, no k/N, no race/cpu/repeat/load keys. Seeded as written, at least four nets are "escaped" on the first nightly and starve-3 is a random red. **Fix:** N2 classifies every entry by polarity, recorded strength and keys; the schema carries them; counter-examples for a `passes` net turning red and for k/N nets (or keep them out with a recorded reason).

**RQ-2 — blocker. "Caught" has no control, so a broken or flaky test reads as caught.** §2 judges only the planted run; the 117 set-aside "revision pairs" are `control: true` entries with no plant — exactly the real code, the one thing re-runnable at HEAD; the nightly tier runs no `unit` or `pytests` row. A test red or flaky at HEAD (on the CI runner, or on macOS) marks every net on it caught; "selects no test" cannot be told from a plant that breaks the build (`mutate.py:76-79`: both `invalid`). **Fix:** one unplanted run per distinct test per nightly, green and selecting exactly one test, else its nets "unjudged" (red); existence decided there, before any plant; record each net's failing (sub)test and first failure line at seeding and print a difference as a line; counter-examples: a test red without its plant, a replace that no longer compiles, a Python plant raising ERROR, a skipped test.

**RQ-3 — should-fix. The §0 counts are off and the sample cannot be reproduced.** By `mutate.changes_of` at HEAD, 33 of the 40 diffs apply and 7 are refused (G10-10, g10-22-revert, g2-117, G10-1-revert and three W0-2 entries on mutate.py): 28 plants no longer apply, not 21. Four standalone `.diff` plants sit outside the 413. There is one `TestLiveEqualsReplay` plant (G2-92). The sample names no script and no ids. **Fix:** correct the counts; commit the selection or list the 24 ids; say what happens to the four `.diff` files.

**RQ-4 — should-fix. Lane A's own library split of mutate.py stales about 67 nets in this sprint; other nets sit on files that change every sprint.** 62 find plants and 5 diffs target `gate/bench/mutate.py`; 67 Python nets run `gate.bench.tests.test_mutate`. G2-15 plants into `gate/current-sprint` (stale at this sprint's first commit, and expected green); G2-24 and PR2Q-13 plant into `gate/law.json` and `gate/registry.json`. **Fix:** seed after the split or re-anchor in the split commit; retire nets on per-sprint files with a reason; count the nets on files this sprint edits.

**RQ-5 — should-fix. "Stale is red" is enforced only by the nightly and a manual `--changed`, which under-selects.** No PR CI row enforces it; any non-rename PR that stales a net merges green. `--changed` misses a changed test helper (`helpers_s3_2b_2_test.go`), an identifier present only in find or replace text, patch nets (no `file` key) and edits to the net's own entry; rewriting with the rename tool can corrupt short-name substrings, gofmt column re-alignment, patch context and py dotted ids; nothing stops deleting a red net. **Fix:** a static stale check as a fast T2 row (file tracked; find once or hunks place; `func TestX(` declared; py id resolves by AST); pin the live count with a `retired` list carrying reasons; rename PRs run the full nets row; counter-examples for a replace-only identifier, a patch net's file, and a deletion without retirement.

**RQ-6 — should-fix. Q2's options misstate the re-cut's binding input.** Its item 2 offers "pin each batch to its recorded commit and map it through the ledger"; Q2(c) dropped the mapping. The binding input also asks for the G3–G6 and G8 measure. **Fix:** restate faithfully, ranked by accuracy; report G3, G4 and G8.

**RQ-7 — should-fix. The macOS proof (17) and exit 5 cannot run as written, and the macOS job can pass vacuously.** Drivers run only in the T4 `proofs` row on ubuntu (`.github/workflows/gate.yml:152-175`); the test rows are T2–T4 and select nothing at `--tier nightly`; nightly.yml's `download-artifact` steps are `continue-on-error: true`; the owner's machine is darwin, so a darwin-only plant makes local T2 red. **Fix:** standing linux proofs (a generator case; summary cases for a missing macOS record) and a one-time dispatched demonstration on a throwaway branch, its run URL in the record.

**RQ-8 — should-fix. The new proofs add to PR CI and risk flakiness in the proofs job.** Every new driver runs in PR CI's `proofs` job (600 s; 227–362 s locally), drivers run in parallel (`gate/runner/rows/__init__.py:140`), and load and stress proofs start hogs. **Fix:** measure each driver; small fixed hogs in the proofs world; deterministic once-in-N plants (a counter file); exit 7 records the proofs job's wall.

**RQ-9 — should-fix. Budgets measured on the wrong machine, one stress limit shared, no burn-in.** N4 measures locally while rows run on slower runners; `STRESS_TIMEOUT_MIN = 25` is one constant for every race-stress row (`gate/runner/rows/race.py:25`); `-count=N` spans every run of every test; `-cpu 1,4` doubles `unit`'s unpinned 10 m; `load.py`'s default `--wall` equals `TIMEOUT_MAX_S`; the nets' per-entry timeouts were tuned locally. **Fix:** measure on the CI runner over at least 3 dispatched nightlies; go `-timeout` ≥ 3× the slowest CI run within `timeout_s`; a per-row `--timeout` in race.py; print each net's wall time; 3 consecutive green dispatched nightlies before PR 2; budget time for the flakes found.

**RQ-10 — should-fix. The timing list cannot detect one stale name or a lost count.** `stress.py` takes modules, not test ids (`gate/runner/stress.py:3`); `load.py` exits 0 when every test that ran is N/N (`gate/bench/load.py:136-147`), so a renamed test drops out and a lost `-count` reads 1/1. **Fix:** counter-examples for one stale name among live ones, each test's N equal to its count, and every repeat row's proof asserting go ran the count.

**RQ-11 — should-fix. The schema drops `subtest` and the per-side targets.** 25 of the 235 applying find plants carry `subtest`, 10 carry `new_test`/`new_py`; without the subtest another subtest can "catch" the plant. **Fix:** the schema carries `subtest`; a subtest net is judged on it alone.

**RQ-12 — should-fix. The nets row starts processes per input.** testing.md rule 2 (the owner's decision of 2026-11-12) asks such a row for a test that its process count does not grow with its inputs. **Fix:** the design note bounds it with that test, or asks the owner for an exception with the per-entry budget pinned.

**RQ-13 — should-fix. No inflow rule; seeding is prose, not a test.** Decision 2026-11-22 A says the nightly re-runs the committed plant batches; the plan freezes today's and seeds once. **Fix:** a T2 check that every plants entry maps to a net's `from` or a reasoned retirement; a sprint-model G5 step.

**RQ-14 — later. Exit proof details.** `gh workflow run nightly.yml --ref <branch>` runs the branch's copy because nightly.yml is on main with `workflow_dispatch:` (inferred); keep new jobs in nightly.yml; the shared `nightly` group can replace a pending dispatch, so record run ids and check for `cancelled`; add main's first scheduled nightly after the merge to G5.

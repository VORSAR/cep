## 2. Findings (ranked)

**F1 — blocker — MUST 11 as written is a data race.** "the row is pooled, `fill` writes in place … 0 above `runtime.Send`'s" (design.md:171, 174) cannot hold for the values slice: `runtime.Send` "takes `e.Values`: the caller MUST NOT change them afterwards" (`internal/runtime/runtime.go:507–508`, enqueue at 545); after `Send` returns the router reads them (`ingest.go:63` via `runtime.go:882`, `798`) and writes into them when a `text_invisibles` slot is declared (`ingest.go:64–66`); the shards buffer the event (`runtime.go:907`, `1271`) and bodies read `r.ev.Values[attr]` later (`internal/plan/plan.go:314`); the recorder reads them on its goroutine (`recorder.go:183`). **Proof S1:** `go test -race -run TestQAScratchSendRetainsValues ./internal/runtime/` → exit 1, `WARNING: DATA RACE` at `ingest.go:63` (output `.../panel/qa/s1.out`). A pooled row reused for the next `SendRow` would corrupt the previous event (wrong detection) and trip the `race` row. `Table.Upsert` is safe to pool (`table.go:173–192` clones every row; `runtime.go:829` copies for the recorder). **Fix (text for MUST 11):** "The pooled object is the row header (the schema binding, the set-mask and the deferred error). The values slice is allocated once per `SendRow` and handed to the engine, which owns it (runtime.go:507). `SendRow`'s budget is `runtime.Send`'s plus one allocation, measured by `testing.AllocsPerRun` on one shard, warm (T22)." **Proof S2** (`.../panel/qa/s2s3.out`): pooled header `0.00`, header+slice fresh `2.00`, per-call `fill` closure `0.00`; **S3** (`.../panel/qa/s3.out`): `runtime.Send` on one shard under `AllocsPerRun` = `2.00`. Tests: T22, T23.

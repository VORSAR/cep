# S1.1a-2 plan check: architecture review (with a pre-mortem)

**What I reviewed.** The draft `docs/sprints/s1-1a-2-plan-check.md` (as committed at 9b59a0f). I checked it against the S1.1a-2 card (sprint-plan.md:144-162), the shared S1.1a plan check (S2-S4, P7, P9, §6, §10), the S1.1a-1 gate design, ADR-0015 §1.1-§1.3 and §3.1/§3.6, DEVELOPMENT.md, the sprint model, the S1.1a-1 record and owner decisions, and the code on this branch (`gate/runner/{main,step,scope,verdict,records,summary,env,scheduler}.py`, `gate/runner/rows/`, `gate/run.py`, `gate/registry.json`, `Makefile`, `ruff.toml`).

**How.** I read the documents and the code. I worked blind of QA. The coordinator time-boxed the job, so I ran no probes. Every git or GitHub Actions behaviour below is marked **inferred**. Code claims cite `file:line`.

**Bottom line.** The plan is the right size and shape, and most of it holds. But design question P1 ("rows run in the checked tree") is not finished, and the S1/P1/P3 seams depend on it. As written, a T1 run would check the pushed commit's wrapper scripts against the work tree's registry, `tools.json` and runner. That is a mix of two laws, and it can miss a detection. Also, the snapshot is placed at `<run_dir>/tree/`, which by default sits inside the work tree (`.gate/runs/…`). So any git command run from the snapshot silently finds the real repository and reads the wrong index and tree. The CI side has smaller gaps:
- the artifact layout and the `--attempt` field are undefined;
- `run.json` (which carries the registry digest) is never uploaded;
- the owner's "record the image version" commitment is missing;
- the exit-line-1 row-list diff cannot match, because parity rows are labelled differently locally and in CI;
- the summarize step needs its own `if: always()`.

Fix the two blockers in the design note (§12) before G1. The rest are one-line seam additions.

**Counts:** 2 blocker, 6 should-fix, 6 later.

## Pre-mortem (three weeks after merge)

- **A1.** The owner bumps ruff in `tools.json` on a branch and switches back to `main` to push an older branch. The pre-push hook checks the old tree's wrappers against the new `tools.json` and registry. `ruff` goes red for a reason the pushed commit does not contain, and the push is refused. In the opposite case (the pushed branch adds a row), T1 passes, and CI is the first to fail. People start reaching for `--no-verify`, which the policy forbids.
- **A2.** S1.1b adds `lawdelta` at every tier. Under T1, its `git diff` runs inside `.gate/runs/<id>/tree/`, finds the real repository, and diffs the work tree's HEAD, not the pushed tip. The LAW Δ block at push time describes the wrong commit, and nobody notices until a law change slips past the owner's reading.
- **A3.** One CI job flakes, and the owner clicks "Re-run all jobs". Attempt-1 and attempt-2 artifacts are merged into one directory. Depending on download order, `strict-gate` is green on one run and red on the next, with the same code. That is the non-deterministic gate that ground rule 11 says stops the line.
- **A4.** A hand-edited workflow passes a fixture `--registry` to one job. Every row id still matches, so `summarize` is green over checks that never ran the real law.
- **A5.** A red push is investigated from its records. The `commit` field names HEAD, not the refused tip, so the owner reproduces it on the wrong commit and finds nothing.
- **A6.** GitHub moves `ubuntu-latest` to a new image. `unit` starts failing on Linux with no commit of ours, and no record shows that the image changed.
- **A7.** At G4 the coordinator diffs the two row lists, sees three parity rows against one, and explains the difference by hand. The exit-line-1 proof is then judgement, not a check that can fail.
- **A8.** The artifact service has an outage. `strict-gate` is red with "download failed" and no row table. The owner re-runs it (a retry), which ground rule 11 forbids, because nothing named which job's records were missing.

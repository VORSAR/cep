## 1. Findings, ranked

### B1 (blocker) — "T4-only" is not what the plan builds: `TestNotBuiltExpired` runs at T2 under `unit`.
*Evidence.* `gate/registry.json` row `unit`: tiers T2–T4, command `unit.py ./...`; `gate/runner/rows/unit.py:23` runs `go test -json -count=1 ./...` with no `-run`/`-skip`; row `race` runs `./...` at T4. A Go test in `./conformance` is therefore executed by `unit` at T2 whatever row is "T4-only" — the registry's tier governs the *row*, not the test. The precedent the plan leans on behaves exactly so: `TestTripwire` (`internal/playback/s3_2b_2_corpus_test.go:197`) has no tier guard and simply passes at T2. A `t.Skip` guard is not an escape: `unit.py:44` turns a skipped test into a failure. So at S4.1's G0 (marker `S4.1`) every lane's T2 is red through `unit` — the exact harm §8 risk 3 says the T4-only row prevents. Counter-example (2) "marker S1.1c-1 → pass" hides this because it passes today.
*Why a question, not a fix.* Decision 9 says verbatim "the not-built expiry runs in a T4-only `gotest` row with T2 unit tests of a pure function over the plan table's row order". The constraint is recorded; the code says a `gotest` row cannot make a Go test T4-only. The owner must pick.
*Options (recommendation first).* **(a) The expiry as a Python row** `gate/runner/rows/notbuilt.py` (reads `conformance/notbuilt.json`, `gate/current-sprint`, `docs/sprints/sprint-plan.md`; T4 only; red naming file, construct, sprint), with the pure grammar and order in `gate/runner/sprintid.py` tested by `pytests` at T2 (decision 9's "T2 unit tests of a pure function" holds), the marker test (decision 8) a `pytests` unit test over the real plan file, and `TestCorpus` keeping a ten-line Go loader for `notbuilt.json` (no order logic in Go). Truly T4-only; one implementation of the grammar, which `lawdelta`'s `marker`/`notbuilt` parsers reuse; no `conformance → tools/sprintid` import (S2 below dissolves). **(b)** keep Go and add `-skip ^TestNotBuiltExpired$` to the `unit` row (a registry law edit; `race` still runs it at T4, which is acceptable). **(c)** an env-guarded early return (`GATE_ROW != "conformance-expiry"` → return) — a silent pass by design, against the sprint's goal; reject.
*Disposition.* §11: a new Q6 citing decision 9, options as above, (a) recommended. §2 S2, §3 rows 1–3, §4 lane B, §7 lane B and §8 risk 3 change with the answer.

### S1 (should-fix) — S3's seam has no channel in the code, and the record schema bump is under-specified.
*Evidence.* The scheduler builds every record itself from `_Done` (`scheduler.py:478–496`, `records.make`); `_Done` (`scheduler.py:64–79`) carries `reason`, never a row's output. A row reaches the scheduler only through stdout markers: `GATE_COVERED` (`rows/__init__.py`, `covered`), `failed: ` / `FAIL ` / `internal error: ` (`step.py:40–50`). "The `lawdelta` row writes its block into its own record" names no mechanism. Then `summarize._valid` (`summarize.py:71–74`) requires `record.keys() == FIELDS.keys()`: a record with an extra `law` key is **malformed** (a RED row, `summarize.py:99–102`), so a `law` key on the one row breaks CI unless `FIELDS` changes and every record carries the key. `_judge` (`summarize.py:129–139`) never compares `record["schema"]` with `records.SCHEMA`: bumping `SCHEMA` gates nothing by itself; the stale/other-commit checks key on `run_id` and `commit`, so the bump leaves them untouched — the plan should say so rather than imply a consequence.
*Recommendation.* §2 S3 states the channel: the row writes `law.txt` (one line per entry) into `GATE_ROW_DIR`; the scheduler reads it when it makes *that* row's record; `records.make` gains `law: list[str]` on **every** record (empty elsewhere) so `_valid`'s equality holds; `FIELDS["law"] = list`; `SCHEMA = 2`. §5 P2 lists this and the fixture tree for the malformed-old-schema case.
*Disposition.* Change §2 S3 and §5 P2.

### S2 (should-fix) — `tools/sprintid` needs a law edit the plan does not list, and §8 risk 8 misreads archcheck's scope.
*Evidence.* `gate/registry.json` row `archcheck`: `expected_scope` is `**/*.go` **excluding** `gate/**` and `tools/**`; its `scope` is `prod, test, bench, generated` (not `tools` as risk 8 says). So `tools/sprintid` itself is under no layer law and no coverage floor (`coverage-inclusion` scope excludes `tools/`); only `gofmt`, `vet`, `unit` and `race` see it. But `conformance/notbuilt_test.go` **is** scanned, and `tools/archcheck/main.go:192` admits a test file's import only through `rules.Imports[key]` or `rules.TestImports[key]`. `tools/importcheck/rules.json` has `"conformance": ["", "rule", "io", "io/*"]` and no `test_imports` entry for it → lane B is red at T2 on `archcheck` the moment the test imports `tools/sprintid`, until the coordinator lands a `test_imports` edit — a law edit (ADR-0015 §1.4) that §4's coordinator row omits and the LAW Δ of this PR would show. ARCHITECTURE §3 also says `conformance/` "imports PUBLIC packages only — it proves the real product path"; a tools import contradicts the letter and needs an annotation. Under B1 option (a) none of this arises.
*Disposition.* If Go stays (B1 b): add `tools/importcheck/rules.json` (`test_imports.conformance: ["tools/sprintid"]`) and the ARCHITECTURE §3 annotation to §4's coordinator row, landing **before** lane B's T2; rewrite §8 risk 8 ("archcheck does not scan `tools/`; it scans the importer"). ### S3 (should-fix) — the `deps` row is red on today's tree by construction, and the plan's §0 missed it.
*Evidence.* Proving run above: `go mod graph` and `go list -m all` both contain `github.com/kr/pretty v0.1.0` and `gopkg.in/check.v1` (through `gopkg.in/yaml.v3`'s go.mod); neither is in `tools/deps-allowlist.json` (21 modules after normalisation). *Also.* 9 of the 24 build-list modules have no `Dir` offline (go-cmp, kr/pretty, goldmark, x/net, x/sys, x/telemetry, the two deprecated x/tools sub-modules, check.v1): the licence-by-fingerprint check cannot read them, and risk 6's "a module with no `Dir` is a named FAIL" would redden the real tree too. State plainly in Q4 that graph-only modules are checked by the owner's hand-entered field, not a file.
*Disposition.* §11: a new Q7 — approve `kr/pretty` (MIT) and `gopkg.in/check.v1` (BSD-2-Clause) as graph-only entries, or exclude test-only sub-graphs from the rule; §2 S4 and §5 P4 take the three sets; §6 deps (7) is rewritten; §0 gains item 11.

### S4 (should-fix) — `lawdelta`'s `blocking` contradicts ADR-0015 §1.3 as written.
*Evidence.* §1.3: "The row is **YELLOW, never blocking** (law must remain changeable) and never absent". Decision 9 and the card: red with no merge base, red on an untracked path. Both hold only if the row is `blocking: true` and PASS on *any* delta (the delta itself is never a failure; only the row's own inability to read is). The plan never states `blocking` or the PASS-on-delta rule, and §4 lists no §1.3 annotation for it.
*Disposition.* §2 S3 adds "`blocking: true`; a delta of any size is PASS; FAIL only for no merge base, an untracked listed path, or a parser crash"; §4 coordinator: annotate §1.3.

## 4. Pre-mortem — three ways this fails us by S4.2, not yet mitigated
1. **The relabel.** S4.1 opens, the marker reads `S4.1`, `unit` goes red at T2 in every lane (B1); an agent "fixes" it by moving `01-agent-kill-switch` to `S4.2` in `notbuilt.json`. 2. **Flag wallpaper.** Every sprint annotates an ADR, so `docs/architecture/adr/ … — an ADR changed — owner decision required` fires on every PR from this one on; by S4.2 the flag is read as noise and a real SPEC edit rides beneath it. Mitigation: the doc flag names the file and the first changed heading (`ADR-0015 §1.3`), so a flag carries what changed.
3. **The toolchain bump.** A Go bump or a goleak bump reshapes `go mod graph` (new indirect test modules); `deps` goes red on `main`'s CI and the fix is an allowlist entry nobody approved in a sprint card. Mitigation: S3's three sets plus a stated rule that a graph-only entry needs only the `why: "required by …"` line and the coordinator's note in the record — not a sprint-card decision.

## Bottom line

Every exit line has a proof, but two of them can pass for the wrong reason.

- **T0's new SKIP rule has no test that it can fail.** The draft does not say where the staged-scope command runs. If it runs in the snapshot directory, which sits inside the outer work tree, every row could expand to nothing. Every row would then SKIP, and the commit would pass (Q1). Only `gofmt` has a "staged in scope, so not skipped" case. `ruff` at T0 has none.
- **Nothing says the hook proof uses the tracked hook files.** A world that writes its own hook proves nothing about `.githooks/` (Q2).

Exit line 1's row-list diff compares the registry with itself (Q3). Exit line 4's footer is only recorded, so it can never be red (Q9).

The design also leaves open:

- which registry T0 and T1 read (Q4);
- which interpreter runs the hook code (Q5);
- how T1 builds its tree: `git archive` plus the installer's rules does not reproduce the commit's tree (Q6).

All of these can be fixed in the design note at G1, before any code.

## Counter-examples to add (input → expected outcome)

- **N12.** Only a staged unformatted `gate/x.py` → refused, naming `ruff` and the file. The same for every row at T0: a staged in-scope defect is never SKIP.
- **N13.** `git commit -a` run from `internal/event/` → the same verdict as from the root.
- **N14.** First commit in an empty repo (no HEAD) with an unformatted `.go` → refused.
- **N15.** HEAD holds an unformatted file (landed with `--no-verify`); `git commit --amend` with nothing new staged → T0 SKIP, as documented; `pre-push` refuses.
- **N16.** A merge without conflicts that brings in an unformatted `.go` → refused by `pre-merge-commit`, or a documented T0 gap that T1 refuses.
- **N17.** `git mv a.go b.go` with unformatted content → refused, naming `b.go`. A staged deletion of an unformatted file → passes.
- **N18.** File names with a space, a leading `-`, a newline, non-UTF-8 bytes, `.complete` at the root, and a case pair → T0 and T1 give the same verdict, and there is no extraction refusal.
- **N19.** A staged symlink `x.go` → `../../outside.go` → nothing outside the snapshot is read; the verdict is defined.
- **N20.** A typo in a T0 row's pathspec → T2 fails (zero is a failure). T0's scope comes from the same `ls-files` engine, so T0 SKIP is never the only sign.
- **N21.** Push of an annotated tag → T1 on the peeled commit. Push of a tip from before the gate → refused with a named reason, never a crash.
- **N22.** Push of branch B while A is checked out, with different registries → B is checked under the law Q4 decides.
- **N23.** An uncommitted broken `gate/registry.json` and a clean pushed tip → the outcome Q4 decides.
- **N24.** `git push` of three refs at two shas, one sha bad → two T1 runs; the push is refused, naming the bad sha.
- **N25.** The hook proof run with `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_CONFIG_PARAMETERS='core.hooksPath'='/nowhere'` and `GIT_OBJECT_DIRECTORY` set → the same result; the real repo's `HEAD`, `index` and `config` bytes are unchanged.
- **N26.** A linked worktree (`git worktree add`) → the hook runs there; the same refusal.
- **N27.** The world's `.githooks/pre-commit` replaced by `exit 0` → the hook proof goes red.
- **N28.** A new driver deleted → the `proofs` row is red (`min_wants`).
- **N29.** `core.hooksPath` set to the absolute path of this repo's `.githooks` → `hooks` PASS. `.githooks/pre-commit` not executable → FAIL.
- **N30.** Planted records from two jobs whose clocks are offset, plus one with `ended_ms < started_ms` → the footer follows the defined formula; that record is RED "inconsistent".
- **N31.** A job's `run.json` `registry_sha256` differs from the registry → RED "stale".
- **N32.** CI's "re-run failed jobs" → `strict-gate` RED, naming the older attempt's rows "stale"; documented as "re-run all jobs".
- **N33.** Artifacts of attempts 1 and 2 both downloaded → only the current attempt counts; the older ones are RED "stale", not "duplicate".
- **N34.** N8 tightened: a docs-only commit → every row SKIP **and** parity PASS (parity never skips).
- **N35.** v1 21 under plain `commit`, `commit -a` and `commit <path>`, pass and refuse → the bytes of `.git/index`, the work tree and HEAD are unchanged.
- **N36.** `python3` on PATH is 3.9.6 → the commit is refused, naming the fix (exit 2).

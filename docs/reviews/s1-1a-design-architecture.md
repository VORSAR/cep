## Failure scenarios (pre-mortem: "S1.1a-1 shipped and failed — why?")

**DA1.** On day 2 of W1, Lane B runs `make check` in its worktree. Every row fails: "can't open file gate/runner/rows/vet.py", because Lane A owns those wrappers. `unit` fails "no test ran". The agent either reports blocked or "fixes" it by adding a test to `internal/event` (QA's area) or by editing the registry (law data). Either way, W1's done rule (REC:65) can't be met as written. The coordinator loses the wave to sequencing, and combine-W1's "first real `make check`" is red for the same reason.

**DA2.** The coordinator's fresh-clone run reaches step 6 and gets `PermissionError: [Errno 13]` on the rename, on the first tool. On a CI runner (non-root Linux) the same happens. If the step order is swapped ad hoc, a race loser then dies in `rmtree` and leaves read-only `tmp.*` directories that `rm -rf` cannot remove. The cache fills with undeletable debris, and users start deleting it by hand with `sudo`.

**DA3.** QA writes `order_test.go` as `package event_test`, which is idiomatic for exported API. `vet` goes red: "covered 2 ≠ expected 1". `coverage-inclusion` is already red: "covered 1 ≠ expected 4", because `.`, `./rule/...` and `./io/...` show up as error entries. The likely ad-hoc fix is to let the wrapper compute its own expected number. That quietly removes GR-13's protection: a self-certifying count.

**DA4.** Lane C writes the version proof as specified, and it fails with "go: not installed". Lane C writes the path proof, and parity passes because the cache comes first on PATH. Under deadline pressure, the "missing" proof asserts only "make tools" and passes on the bootstrap's refusal. Exit 2 is then "proven" by a test that never reaches parity's not-installed code.

**DA5.** In S1.1a-2 the same runner sits behind every commit hook. Pressing Ctrl-C during `unit` does nothing for minutes. The user presses it again (that only skips the grace period, and the flag is still unseen), then runs `kill -9`. The rows survive in their own sessions, there is no summary, and the next run's watchdog fires under the leftover load. Hooks get `--no-verify`'d.

**DA6.** In S1.1b a coordinator adds an exclusive benchmark row before the build row it needs. Locally `make check` hangs with zero CPU use. No watchdog fires because nothing is running, and the overall ceiling was never specified.

**DA7.** A row wrapper starts `go test` in the background and exits 0 with the right count. The runner sees a live group member, but the verdict list has no rule for that, so it records PASS. QA's C4 then contradicts the normative list, and the lane has to pick one.

**DA8.** The owner picks (b), believing both traps are closed. In S3.2a the playback loader builds `event.Schema{Stream: s, Attrs: attrs}` by literal and forgets `TimeAttr`. Attribute 0 (say `agentId`, a string) becomes event time. Orders are wrong and detections are missed, and nothing flags it, because the trap the owner was told was closed is still open.

**DA9.** Lane A's runner has dozens of S603/S607 hits. The agent adds bare `# noqa: S603,S607` everywhere, which DEVELOPMENT's `//nolint` grammar does not cover. S1.1b's `suppressions` checker reads Go only, so the gate's Python ends up with unaccountable suppressions: a "third state". Meanwhile ruff's UP rules rewrite `Optional[str]` to `str | None` in `bootstrap.py`. pyfloor passes, and Apple's 3.9.6 crashes at import.

**DA10.** A later edit to `bootstrap.py` uses `hashlib.file_digest`. Every gate row is green. On a new Mac without Homebrew Python, `make tools` dies with an AttributeError, and the clean-clone promise (exit 1) breaks.

**DA11.** In S1.2 someone deletes `test_ruff_sleep.py` and `git rm`s it. Covered drops to 8, and expected (live) drops to 8 too, so the row stays green. Separately, every T2 run already executes all nine proof drivers inside `pytests`. T2 slows down and `pytests` times out under load.

**DA12.** In S1.1a-2 the CI footer prints "wall 0.0s · saved 99%" or a negative number, because it compares `time.monotonic_ns` readings from different runner machines. Exit 4's measured saving is meaningless.

**DA13.** In S3.x `io/http` brings `net` in. On the Linux CI image with `CGO_ENABLED=1`, `go test` now runs `pkg/tool/linux_amd64/cgo` and the image's `gcc`. Neither is hashed, while the summary still claims every executable is verified.

**DA14.** The owner has `GOARCH=amd64` exported from a Rosetta session. `make check` builds amd64 test binaries and runs them under emulation. The result is green, but it is a different run from CI, and parity cannot tell.

**DA15.** The coordinator's fresh-clone run prints "run `make tools`" and `exit: 2`. Exit 1 is red until the Makefile is changed ad hoc.

**DA16.** In S1.1a-2 `summarize` looks for `records/lint/parity.json` in a locally made fixture tree, finds `records/*/parity.json` (or nothing), and fixture trees disagree with real runs.

**DA17.** The python-build-standalone archive turns out to contain one hard-link member. "Reject a hard link" makes `make tools` fail on that platform, and exit 1 is blocked until the rule changes mid-wave.

**DA18.** A W1 lane passes the scaffold using Homebrew's go 1.27.3 with no cache on PATH, and its tests depend on that environment. At combine-W1 the real runner sets PATH and the environment differently, and new reds appear in the one step that has no slack.

## P1 view (zero values)

**I agree with (b) for `Type`, but the note sells it on the wrong reason and promises more than it delivers for `Schema`.**

In plain words:
- **The strongest reason for (b) is missing from the note.** Under (a), no checker, however careful, can ever spot a forgotten text slot. A forgotten slot and a real empty text are the same value. In a number slot, a checker could at least see the wrong kind. Option (b) gives "forgotten" its own visible value (`TInvalid`) for almost no cost today, because no code uses these types yet.
- **(b) makes the mistake visible. It does not catch it.** Nothing in this sprint reads `Kind` (the note defers accessors). The typed accessors that arrive later MUST refuse `TInvalid`. The ARCHITECTURE annotation should say that `TInvalid` never appears in a schema or in any value after ingest, and that it is never a null (nulls keep their declared type, ARCH:187-189, SEMANTICS §1.1).
- **The schema half is only half fixed.** `NewSchema` protects only callers who use it. Because `Schema`'s fields stay public, `Schema{Stream: "s", Attrs: a}` still compiles and still means "attribute 0 is the event time". To truly close it, make `Schema`'s fields private with read-only accessors, so the constructor is the only way in. A schema is built once per stream and is never on the hot path, so this costs nothing at run time; it is a bigger ARCHITECTURE §4 change. If the owner prefers not to, the gap should be written down as review-only residue, not described as closed.
- **One rule in `NewSchema` is new language law.** "The event-time attribute must be a timestamp" is not in SPEC (SPEC:75) and has no error code (errors.md:73-79). It belongs in S1.2's spec rev-3 batch as a coded validator error. `NewSchema` stays an internal safety net that users never see.
- **No conflicts found:** the SPEC and SEMANTICS type lists are unchanged (`TInvalid` is not a language type); the null rule is unchanged; ADR-0003/ADR-0006 encode through canonical JSON, which has no numeric `Type` today (pin "by name" in S1.2; DA24); no later sprint card relies on `TString` = 0 (searched); QA's earlier "TString=0 … TObject=6" pin (QA Q4) is re-pinned as 1…7.
